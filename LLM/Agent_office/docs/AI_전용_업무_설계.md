# AI 전용 업무 설계 — '사람을 돕는 도구'에서 '사람이 안 하는 일을 하는 팀'으로

작성일: 2026-10-29 · 상태: 설계 + 0단계 시제품 + 1단계 완료(🛡️ 보안 거버넌스 팀 공개, 자율 실행은 기본 꺼짐)

## 1. 한 줄 요약

가능하다. 지금 Agent Office의 핵심 부품(조직도 워크플로우, 하네스, 비평가, 팀원별 모델, 비용 기록)은 그대로 쓰면 된다. 바꿀 것은 세 가지다.

1. **누가 시작하나:** 사람의 질문 대신 스케줄·이벤트가 시작한다.
2. **어디까지 스스로 하나:** 자율 수준을 정하고, 허용 목록 밖의 행동은 하지 않는다(기본 거부).
3. **어떻게 믿나:** 비용 상한, 해시 체인 감사 로그, 그리고 사람 승인 대기열을 둔다.

첫 단계는 **🛡️ 보안 거버넌스 팀이 주 1회 통제 점검 보고서만 쓰는 것**(observe)이다. 0단계에서 뼈대(7장)를, 1단계에서 팀 공개·공개 통제 목록·검증기 2개·상태 화면(7-1장)을 만들었다.

## 2. 지금 구조 — 사람이 매번 시작하고 매번 결정한다

```
사람 질문 → brief → research → work(분배·초안·검토·통합) → 사람 결정(interrupt) → 교훈
```

- 모든 실행은 화면에서 사람이 시작한다. 예외가 두 가지 있다.
  - 뉴스·SNS 수집(`core/feeds.py`)은 24시간마다 백그라운드에서 돈다.
  - 평가 하네스(`evals/run_eval.py`)는 사람 결정 없이 끝까지 돈다.
- 결과는 사람이 채택, 수정 또는 반려한다. 사람이 읽을 수 있는 양만큼만 일이 돈다.

이 두 예외가 자율 실행의 선례다. 피드 수집은 **주기 실행 + 비용 기록 + 프롬프트 주입 방어**를, 평가 하네스는 **사람 없이 그래프를 끝까지 돌리는 법**을 이미 보여 준다.

## 3. 'AI만 할 수 있는 업무'의 기준

사람보다 똑똑해서가 아니라, 다음 넷 중 하나 때문에 사람이 현실적으로 하지 않는 일이다.

| 기준 | 뜻 | 예 |
| --- | --- | --- |
| 양 | 한 번에 대조할 항목이 수백~수천 개 | ISMS-P 인증기준 101개 × 사내 정책 문서 수십 개 |
| 주기 | 매일·매시간 반복해야 의미가 있음 | 설정 변경(drift)을 매일 점검 |
| 지루함 | 사람이 하면 빠뜨리는 기계적 대조 | 통제 항목마다 증적 문구를 하나씩 인용 |
| 대량 생성 | 시험용 변형을 수천 개 만들어야 함 | 탐지 룰 우회 변형으로 내 탐지 모델 시험 |

**사람의 역할은 바뀐다.** 매 질문에 답을 고르는 대신 세 가지를 맡는다.
- 예외를 처리한다.
- 승인 대기열을 결정한다.
- 주간 요약을 읽는다.

## 4. 후보 업무 평가

점수는 높음·중간·낮음으로 매겼다. '검증'은 LLM 출력을 코드로 확인할 수 있는 정도다. 이 프로젝트의 원칙은 '숫자·형식은 코드로 다시 계산'이다.

| 후보 | 가치 | 검증 가능성 | 잘못될 때 피해 | 첫 자율 수준 | 판단 |
| --- | --- | --- | --- | --- | --- |
| ① 통제 점검·증적 정리 (ISMS-P · ISO/IEC 27001:2022 · NIST CSF 2.0) | 높음 | 중간: 통제 번호·JSON 형식·인용 문구 존재 여부는 코드로 확인 | 낮음 (보고서) | observe | **1순위** |
| ② 설정 drift 점검 (어제와 오늘 설정 비교 → 통제 영향) | 높음 | 높음: diff 자체는 코드 | 낮음 | observe | 1순위와 묶음 |
| ③ IaC·쿠버네티스 매니페스트 정적 점검 + 수정안 | 높음 | 높음: 오픈소스 스캐너 결과 + 수정 후 재검사 | 중간 (적용 시) | propose | 2순위 |
| ④ 규제 ↔ 내부 정책 대량 교차 대조 (AI 기본법·EU AI Act 의무 vs 정책 문서) | 중간~높음 | 낮음~중간: 조문 인용 존재만 확인 가능 | 중간 (해석 오류) | observe | 3순위, 사람 검토 필수 |
| ⑤ 탐지 룰 우회 변형 대량 생성 (내 탐지 모델 시험용) | 높음 | 높음: 룰 매칭·모델 점수는 코드 | 중간 (유해 페이로드 취급) | observe, 오프라인 전용 | 3순위 |
| ⑥ 지식 카탈로그 상시 유지 (링크 깨짐·중복·요약 누락) | 중간 | 높음 | 낮음 | propose | 이미 있는 개념 팀 확장 |
| ⑦ 피드 자동 분류·위협 동향 요약 | 중간 | 낮음 | 낮음 | observe | 피드 수집에 보안 소스 추가 |

④는 다음 법·규제의 공개된 의무 목록을 대조 기준으로 쓴다.
- **AI 기본법:** 2026-01-22 시행, 고영향 AI 사업자 의무 6가지.
- **EU AI Act:** Digital Omnibus로 고위험 의무 적용일이 2027-12-02(Annex III)로 미뤄졌다.

해석은 바뀔 수 있으므로 결과는 "조문 X와 정책 문장 Y가 대응하는지 사람이 확인할 목록"으로만 낸다.
출처:
- https://byline.network/2026/01/21-545/
- https://www.gibsondunn.com/eu-ai-act-omnibus-agreement-postponed-high-risk-deadlines-and-other-key-changes/

⑤는 다음 원칙을 지킨다.
- 실제 대상에 보내지 않고 내 탐지 룰·모델에 오프라인으로만 넣는다.
- 결과는 "탐지됨 / 우회됨" 통계로 남긴다.

검토 모델이 위험 유형 샘플을 거부하는 일은 이미 겪었다. 그래서 생성은 인코딩·대소문자·공백 같은 형식 변형 위주로 하고, 변형마다 코드로 룰 매칭을 다시 확인한다.

## 5. 구조 변경

### 5.1 트리거

| 종류 | 방법 | 시제품 |
| --- | --- | --- |
| 스케줄 | 작업 스케줄러가 `scripts/run_autonomous.py`를 1시간마다 부르면, `every_hours`가 지난 작업만 돈다 | ✅ |
| 이벤트 | 감시 폴더의 설정 파일 해시가 바뀌거나, 저장소 push가 있거나, 피드에 새 보안 공지가 오면 작업을 대기열에 넣는다 | 다음 단계 |
| 수동 | 화면 '지금 실행' 버튼 | 다음 단계 |

마지막 실행 시각은 감사 로그의 `run_start` 줄에서 읽는다. 상태 파일을 따로 두지 않는다.

### 5.2 자율 수준 (기본 거부)

| 수준 | 스스로 해도 되는 것 | 그 밖의 행동 |
| --- | --- | --- |
| observe | 읽기, 보고서 저장 | 승인 대기 |
| propose | 위 + 바꿀 내용을 '제안' 파일로 저장 (수정 PR 초안, 정책 문구) | 승인 대기 |
| (만들지 않음) | push, merge, 삭제, 외부 전송, 설정 적용, 배포 | **어느 수준에서도 항상 사람 승인** |

`core/autonomy.py`의 `gate()`는 허용 목록에 없는 행동을 모두 `approval`로 돌린다. 모르는 행동 이름도 마찬가지다. 승인 대기 항목은 실행하지 않고 감사 로그에 `approval_requested`로만 남긴다.

되돌릴 수 있는 행동 일부(예: 내 포크에 초안 PR 만들기)를 자동으로 허용하는 수준은, 6개월 운영 기록을 보고 판단한다.
- 기준: propose 제안의 사람 채택률, 그리고 하네스 통과율.

### 5.3 비용 상한

- `daily_budget_usd`: 오늘 모든 LLM 호출의 추정 비용 합계(🏠 사용량과 같은 DB)가 이 값 이상이면 새 실행을 시작하지 않는다. 진행 중인 실행은 끝까지 간다.
- `max_runs_per_day`: 무료·구독 모델은 비용이 0으로 잡히므로 실행 수로도 막는다.
- 자율 실행 호출에는 `usage.scope(purpose="자율 실행")`을 붙인다. 그래서 🏠 사용량 화면에서 자율 실행 비용만 따로 보인다.
- 팀원별 모델 선택을 그대로 쓴다. 자율 실행 팀은 실무자를 저비용·무료 모델로 두고 팀장만 상위 모델을 쓰는 것이 기본이다. '부하는 상사보다 낮은 모델' 규칙도 그대로 적용된다.

### 5.4 신뢰 장치 (이미 있는 것을 재사용)

| 장치 | 재사용 | 자율 실행에서의 역할 |
| --- | --- | --- |
| 하네스 (결정론적 검증) | `core/harness` | 검증을 통과하지 못한 결과는 보고서에 '미검증'으로 표시한다. 사람이 없으니 가장 중요하다 |
| 비평가·자가 교정 | `core/verification.py` | 최선안 유지와 심각도 기준을 그대로 쓴다 |
| 프롬프트 주입 방어 | `core/feeds.py`의 표시선 방식 | 피드·외부 문서는 '데이터'로만 넣는다 |
| 감사 로그 | **새로 만듦** `core/autonomy.py` | 줄마다 앞 줄 해시를 넣는다. 고치거나 지우면 `verify()`가 줄 번호를 찾고, 어긋나면 스크립트가 실행을 멈춘다 |
| 킬 스위치 | `settings.yaml`의 `autonomy.enabled` | false면 아무것도 하지 않고 로그도 남기지 않는다 (기본값) |
| 외부 유출 방지 | 팀 설정 | 거버넌스 팀은 `web_search`를 끈다. 웹 검색어는 질문(내부 설정·정책)으로 만들어지기 때문이다 |

감사 로그 자체가 거버넌스 증적이다. ISMS-P·ISO 27001이 요구하는 '로그 무결성'을 이 앱이 스스로 지키는 예가 된다.

## 6. 위험과 막는 법

| 위험 | 예 | 막는 법 |
| --- | --- | --- |
| 잘못된 판정을 사람이 믿음 | 지어낸 통제 번호, 없는 증적을 '충족'으로 | ① 증적 없으면 '확인 불가' 규칙 ② 통제 번호를 공개 목록과 대조하는 검증기 (1단계) ③ 인용 문구가 입력에 실제로 있는지 코드로 확인 (1단계) |
| 잘못된 행동 | 수정안을 운영 설정에 바로 적용 | 기본 거부 게이트. 적용 행동은 구현 자체를 하지 않는다 |
| 비용 폭주 | 실패한 작업이 매시간 재시도 | 일 예산과 일 실행 수 상한. 실패해도 `run_start`로 세어 다음 주기까지 기다린다 |
| 민감정보 유출 | 내부 설정이 외부 LLM·검색으로 | 웹 검색을 끈다. 입력에서 비밀 값을 지우라고 안내한다. 다음 단계에서 비밀 패턴 마스킹 검증기를 추가한다. 민감한 입력은 로컬·사내 모델로 돌린다 |
| 유해 생성물 | 룰 우회 변형이 실제 공격에 쓰임 | 오프라인 평가 전용으로 쓰고, 저장소에는 통계만 올린다. 형식 변형 위주로 만든다 |
| 조용한 실패 | 몇 주째 실행이 안 됐는데 모름 | 🏠 메인의 '🤖 자율 실행' 패널에 마지막 실행·다음 실행·승인 대기열과 감사 로그 검증 결과를 띄운다 (1단계에서 완료, 7-1장) |
| 로그 조작 | 승인 요청 기록 삭제 | 해시 체인으로 막는다. 어긋나면 실행을 멈춘다 |

## 7. 0단계 시제품

| 파일 | 내용 |
| --- | --- |
| `core/autonomy.py` | 작업 설정(pydantic), 주기 판단, 일 예산·실행 수 상한, 기본 거부 게이트, 해시 체인 감사 로그, `run_due()` (runner는 함수로 받음) |
| `scripts/run_autonomous.py` | `--dry-run`은 호출 없이 때가 된 작업, 오늘 비용, 로그 상태를 보여 준다. 실제 실행은 평가 하네스와 같은 방식(사람 결정 없음)으로 하고, 보고서는 `data/autonomy/reports/`에 저장한다 |
| `teams/_security_governance/team.yaml` | 보안 거버넌스 팀 뼈대. '_'로 시작해 아직 화면 팀 목록에 나오지 않는다 (1단계에서 `teams/security_governance`로 공개). 업무 '통제 항목 점검'의 결과는 JSON(`summary`, `controls`)과 필수 항목 검증을 거친다 |
| `config/settings.yaml` → `autonomy` | `enabled: false`, 예산 $1/일, 6회/일, 작업 없음 (예시는 주석으로) |
| `tests/test_autonomy.py` | 8건: 기본 꺼짐, 주기, 예산 상한, 실행 수 상한, 승인 대기, 실패 기록, 로그 조작 탐지, 팀 설정 유효성 |

켜는 법은 다음 순서다. 실제 API 비용이 든다.
1. `settings.yaml`에 작업을 넣고 `enabled: true`로 바꾼다.
2. `python scripts/run_autonomous.py --dry-run`으로 계획을 확인한다.
3. 작업 스케줄러에 1시간마다 등록한다.

## 7-1. 1단계 — 🛡️ 보안 거버넌스 팀 공개 (2026-10-29 완료)

- 통제 점검은 일부러 넣은 미비점 다섯 개를 모두 표에 올렸다. 다섯 개는 퇴사자 계정, 412일 된 서비스 키, 로그 보관 180일(정책 1년), RDP 3389 전체 허용, SSH 비밀번호 로그인이다.
- drift 비용의 75%($0.2586)는 팀장 검토 1회가 대안 모델 gpt-5.5로 넘어간 데서 나왔다(출력 7,356 토큰). 팀장 대안 목록을 저비용 모델로 묶으면 줄어들 것으로 보이지만, 아직 측정하지 않았다.
- drift 점검은 서비스 키 나이(405→412일)처럼 날짜만 바뀐 줄도 '약화'로 적었다. 날짜 줄을 diff에서 빼는 규칙은 아직 없다.
- 실행 1회씩이라 통과율로 일반화할 수 없다. 주 1회 운영 기록이 쌓이면 다시 잰다.
