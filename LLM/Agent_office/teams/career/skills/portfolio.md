[포트폴리오 — 형식 우선순위]
- 사람이 형식을 정했으면(추가 요청의 '기존 문서 형식과 유사하게', 근거 자료의 '형식 참고 파일', 지금 포트폴리오의 형식을 유지하라는 말) 그 형식이
  아래 '표준 형식'보다 우선한다. 원본의 절 제목·표 머리글·표 칸 순서를 그대로 쓴다 (코드가 원본 절 제목·표 머리글이 결과에 있는지 확인한다).
- 요청 형식을 '부록'으로 뒤에 미루지 않는다. 표준 형식으로 다시 쓴 본문 + 부록의 요청 형식은 틀린 답이다.
- 출력 형식이 여럿이면(예: Word 는 기존 Word 경력서 표 형식, md 는 기존 md 경력서 형식) 형식마다 본문을 하나씩 쓴다 — '형식별 본문' 참고.
- 바뀌지 않은 표·항목도 빠짐없이 전부 쓴다. '나머지는 원문 그대로 둡니다' 처럼 생략하지 않는다. ('바뀐 점' 표는 코드가 부록에 붙인다)
- 아래 '표준 형식'은 형식 지정이 없을 때의 기본값이다.

[포트폴리오 — 표준 형식 (형식 지정이 없을 때)]
아래 순서와 제목을 지킨다 (형식 지정이 없으면 코드가 절 제목과 카드 항목을 확인한다).

```
# 포트폴리오 — (목표 직무)
## 요약
(3~5줄: 누구인지 · 가장 강한 경험 2개 · 목표 직무에서 할 수 있는 일)
## 핵심 역량
| 영역 | 기술·도구 | 근거 (문서의 경험) |
|---|---|---|
## 프로젝트
### 1. 프로젝트 이름 (기간)
- **문제**: 무엇이 왜 문제였나
- **역할**: 내가 맡은 일 (팀 규모·내 비중은 문서에 있을 때만)
- **기술**: 쓴 기술·도구·표준
- **결과**: 문서의 숫자로 (전/후)
- **배운 점**: 다음에 다르게 할 점 · 목표 직무에서 쓸 곳
## 직무 강점
- (목표 직무 관점의 강점 3~5개, 각각 근거 프로젝트 번호)
```

[포트폴리오 — 형식별 본문 (출력 형식마다 원본 형식이 다를 때)]
- 본문을 형식 구간 표시로 나눈다. 표시 줄은 글자 그대로 쓰고, 표시 밖에는 본문을 쓰지 않는다 (JSON 블록은 맨 끝에 하나).
  <!-- format:docx -->  (Word 용 본문 — 원본 Word 의 표·절 형식)
  <!-- format:md -->    (md 용 본문 — 원본 md 의 형식, mermaid 흐름도 포함)
- 코드가 .docx · .hwpx 에는 docx 구간을, .md 에는 md 구간을 쓴다. 두 구간의 사실·숫자·날짜는 같아야 한다 (형식만 다르다).
- 형식이 하나뿐이면 구간 표시를 쓰지 않는다.

[포트폴리오 — 쓰는 법]
- 원문의 큰 구분(예: 대학원 · 군 · 회사 · 개인 프로젝트)과 그 순서를 지킨다. 회사 업무와 개인 프로젝트를 섞지 않는다.
- 목표 직무가 중요하게 보는 프로젝트를 앞에 둔다 — **같은 구분 안에서만** (아래 직무 관점 참고). 직무와 먼 경험은 짧게 묶는다.
- 원문의 분류가 모호하면(예: 개인 작업이 '업무 명'으로 회사 표 사이에 있음) 옮기지 말고 원래 자리에 두고, needs_check 맨 위 '결정이 필요한 질문'에 적는다.
- 같은 흐름의 업무(예: 반기별 모델 개선 + 피처 개선 버전 + 학습 데이터 생성)는 사람이 요청하거나 승인했을 때만 합친다.
  합칠 때는 하위 항목마다 원래 이름과 원래 기간을 남기고, 합친 근거(같은 모델 라인인지 등)를 needs_check 에 적는다.
- 기술 매트릭스는 '써 본 것'만. 수준(상·중·하)은 문서에 근거가 있을 때만 쓰고, 없으면 근거 칸에 경험을 적는다.
- 분량: 간단 = 프로젝트 2~3개, 보통 = 3~5개, 상세 = 문서의 모든 프로젝트. (형식 지정이 있으면 원본의 모든 항목)
- 결과 숫자가 문서에 없으면 '결과' 줄에 바뀐 상태를 쓰고 숫자를 지어내지 않는다.
- '배운 점'·'직무 강점'은 카드마다 다른 구체적인 내용으로 쓴다: 그 프로젝트에서 실제로 바꾼 것, 다음에 다르게 할 것 한 가지(문서에 있는 것),
  문서에 없으면 이 경험을 쓸 일의 이름을 짧게. 교훈 한 줄('~의 중요성')로 채우지 않는다 ('문체 — 본인 글처럼 쓰기').
