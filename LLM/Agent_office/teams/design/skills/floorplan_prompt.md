평면 설계는 '좌표 그리기'가 아니라 **레이아웃 JSON 쓰기**다. 좌표 계산·문/창 배치·검증·도면 그리기는 코드가 한다.
(AI-Architect·Text-to-Layout·Text2BIM·ProCAD 의 공통 결론: LLM 은 위상(어떤 방이 어디에, 무엇과 이웃하는지)을, 코드는 기하(좌표)를 맡을 때 가장 정확하다.)
코드의 배치 엔진(OR-Tools CP-SAT)은 방을 0.3m 격자 위 직사각형으로 놓으면서 **구역·이웃 관계·외벽(채광)·장단변비·짧은 복도**를 지킨다.
그러니 LLM 이 할 일은 좋은 **프로그램**(방 목록·면적·구역·이웃 관계·묶음·외곽 유형)을 쓰는 것이다.

## 0. 역할 (아래에서 위로)
- **대리·방프로그램**: 아래 1~2단계만 한다 — 요구사항 정리, **해석·가정 목록**, **층별 방 프로그램표**(층·방 종류(type)·이름·목표 면적·구역(zone)·꼭 이웃할 방·묶음(suite)), 면적 합 계산, 외곽 유형 제안.
  좌표와 레이아웃 JSON 은 쓰지 않는다 (브리프의 'JSON' 완료 기준은 차장 이후 단계의 몫). 수정 업무면 첨부 JSON 에서 무엇을 바꿀지 목록으로 정리한다.
- **차장·배치설계**: 대리의 방 프로그램을 3단계 형식의 **레이아웃 JSON** 으로 옮긴다 (zone·adjacent·open_to·suite·typology 포함). 검토 단계지만 승인(approve)으로 넘기지 말고
  verdict=revise, revised_answer 에 본문 + 전체 JSON 블록을 쓴다 (JSON 이 없으면 하네스가 다시 쓰게 한다).
- **부장·평면검토**: 5절 기준(동선·채광·프라이버시·구역)과 하네스의 '설계 지표'로 검토하고, 고칠 때도 전체 JSON 을 다시 쓴다.
- **팀장·요구사항**: 요구사항과 대조하고 가정을 명시해 최종본을 낸다.

## 1. 해석·가정 먼저 (대리가 표로 쓴다)
애매한 입력은 **해석을 하나 골라 '가정'으로 분명히 적는다** — 조용히 고르지 않는다. 다른 해석이면 무엇이 달라지는지도 한 줄로.
- 면적 단위: '100평' 은 **대지**인지 **연면적(건물 바닥 합)**인지. 1평 = 3.3058㎡ (100평 ≈ 330.6㎡). 대지라면 건폐율(예 50~60%)로 건물 바닥을 줄인다.
- 층수: 층수가 없으면 대지·방 수로 정하고 가정에 적는다.
- 특수실: 수영장·사우나·차고·온실이 **실내(본채 안)**인지, **별동 날개(ㄱ·ㄷ자로 꺾인 동)**인지, **별채/옥외**인지.
  큰 수영장·차고(20㎡ 이상)는 코드가 **일자형 외곽의 한쪽 끝 블록(깊이 전체)**에 넣는다 — 빈 마당 없이 꽉 찬 외곽.
  날개동을 원하면 `"placement": "wing"`(ㄱ자, 안쪽 모서리는 데크로 그린다), 따로 짓는다면 `"placement": "annex"`(별채).
- 마당·중정·데크: 의뢰인이 **요청했을 때만** 방 목록에 넣는다 — `{"type": "other", "name": "마당", "area": 40}` (데크·테라스도 같은 식),
  중정은 `{"type": "other", "kind": "court", "name": "중정", "area": 30}`. 요청하지 않은 빈 마당(ㄱ·ㄷ자로 꺾여 남는 빈 곳)은 오류다.
- 식구 구성: 침실 수·안방 욕실·드레스룸 유무, 손님방·서재 필요 여부.

## 2. 방 프로그램 (구역 · 이웃 · 묶음)
1. 층마다 방의 종류(type)·이름·목표 면적(area)을 정한다. **목표 면적 합 ≈ 바닥 면적 × 0.9** (복도·계단 몫 약 10%, 2층 이상은 계단 6~8㎡ 더).
2. 구역(zone)을 정한다 — `public` 공용(현관·거실·식당·주방) / `private` 개인(침실·서재·드레스룸) / `wet` 물 쓰는 곳(욕실·다용도실·사우나) / `special` 특수(수영장·차고·중정).
   공용은 현관 가까이, 개인은 안쪽, 물 쓰는 곳은 한데 모은다 (배관). 비워 두면 종류별 기본값.
3. 이웃 관계: `adjacent`(꼭 맞닿아 문을 낼 방), `near`(가까우면 좋은 방), `open_to`(벽 없이 트인 방 — 거실·식당·주방 LDK).
   - 기본값(비워 두면 코드가 채움): 주방–식당 꼭 이웃, 거실–식당·현관–거실·주방–다용도실·사우나–욕실·수영장 가까이.
4. 묶음(suite): 안방 + 드레스룸 + 안방 욕실처럼 **안방을 거쳐 들어가는 방**은 같은 `"suite": "master"` 를 쓴다 (딸린 방은 복도에서 직접 들어가지 않는다).
   비워 두면 안방(이름에 '안방') + 드레스룸 + 욕실이 2개 이상일 때 마지막 욕실을 안방 묶음으로 잡는다.
5. 외곽 유형(`typology`): `rect` 일자형 / `L` ㄱ자형 / `U` ㄷ자형 / `courtyard` 중정형 / `auto`(코드가 고름). **보통은 `auto`(또는 비움)**.
   - 기본은 꽉 찬 일자형(가로:세로 약 1.3~1.6, 외곽 효율 = 실내 바닥 ÷ 외접 사각형 ≥ 85%). 실제 단독주택·데이터셋 평면의 다수가 직사각형이다
     (`teams/design/skills/plan_references.md`).
   - ㄱ·ㄷ·중정형은 이유가 있을 때만: 마당·중정을 요청함 / 대지 모양 / 날개동 요청. 꺾여서 남는 빈 곳은 코드가 마당·데크(외부)로 그린다.
   - 코드는 다른 외곽(비율·별채·ㄱ자+데크)·현관 방향으로 **후보안 A/B/C** 를 함께 만들어 화면에서 비교·채택하게 한다.

## 3. 레이아웃 JSON 형식 (단위 m, x→동쪽, y→북쪽, 원점 = 건물 남서쪽 모서리)
```
{
  "title": "4인 가족 단층 주택",
  "outline": {"w": 20, "h": 12},             // 건물 바닥 (가로 w × 세로 h, 마당 제외). 유형이 ㄱ·ㄷ·중정이면 코드가 같은 넓이로 꺾은 외곽을 만든다
  "typology": "auto",                         // auto(권장) · rect · L · U · courtyard
  "wall": {"exterior": 0.2, "interior": 0.12},
  "floors": [
    {"level": 1, "height": 2.8, "rooms": [
      {"id": "entry",   "type": "entrance", "name": "현관", "area": 6,  "zone": "public"},
      {"id": "living",  "type": "living",   "name": "거실", "area": 36, "zone": "public", "open_to": ["dining"]},
      {"id": "dining",  "type": "dining",   "name": "식당", "area": 14, "zone": "public", "open_to": ["kitchen"]},
      {"id": "kitchen", "type": "kitchen",  "name": "주방", "area": 12, "zone": "public", "near": ["util"]},
      {"id": "master",  "type": "bedroom",  "name": "안방", "area": 20, "zone": "private", "suite": "master"},
      {"id": "dress",   "type": "dressroom","name": "드레스룸", "area": 6, "suite": "master"},
      {"id": "mbath",   "type": "bathroom", "name": "안방 욕실", "area": 5, "suite": "master"},
      {"id": "bed2",    "type": "bedroom",  "name": "침실2", "area": 12},
      {"id": "bath",    "type": "bathroom", "name": "욕실", "area": 5, "zone": "wet"},
      {"id": "util",    "type": "utility",  "name": "다용도실", "area": 4, "zone": "wet"},
      {"id": "sauna",   "type": "other", "kind": "sauna", "name": "사우나", "area": 6, "zone": "wet", "near": ["bath"]},
      {"id": "pool",    "type": "other", "kind": "pool",  "name": "실내 수영장", "area": 60, "zone": "special"},
      {"id": "yard",    "type": "other", "name": "마당", "area": 40}   // 의뢰인이 마당을 원할 때만 — 실내 바닥이 아님
    ]}
  ],
  "three_d": false,
  "assumptions": ["'100평'을 연면적(약 330㎡)으로 해석", "수영장은 본채 동쪽 끝에 실내로 둠"],
  "needs_check": []
}
```
- `type`: living, kitchen, dining, entrance, office, bedroom, bathroom, utility, storage, dressroom, balcony, corridor, stair, other
  - 사우나·수영장·차고·팬트리·중정은 `"type": "other"` + `"kind": "sauna" | "pool" | "garage" | "pantry" | "court"` (이름에 '사우나'·'수영장' 이 있어도 알아본다).
  - 마당·데크(테라스)는 `"type": "other"` + `"kind": "yard" | "deck"` (이름 '마당'·'데크'·'테라스' 로도) — 코드가 실내에서 빼서
    ㄱ자 안쪽 모서리(없으면 건물 앞)에 **바깥 공간**으로 놓고 `outdoor` 에 담는다. 바닥 면적·목표 면적 합에 넣지 않는다.
- 선택 항목 (비워 두면 코드가 종류별 기본값): `zone`, `adjacent`, `near`, `open_to`, `suite`, `exterior`(외벽 필요 여부 — 거실·침실·서재는 기본 true),
  `placement`(`main` 본채 / `wing` ㄱ·ㄷ자 날개 / `annex` 별채 — 별채는 본채 도면에서 빼고 메모에 남긴다).
- **좌표(rect)를 쓰지 않으면 코드가 배치한다** (권장). 복도·계단은 코드가 만든다 (직접 넣지 않아도 된다). 여러 층이면 계단이 **모든 층의 같은 자리**에 생긴다.
  - 예전 방식의 `"zone": "front" | "back"`(남쪽/북쪽 띠)도 그대로 받는다 — 배치 엔진이 실패해 단순 분할로 대신할 때만 쓰인다.
- 좌표를 직접 쓸 때(기존 도면 수정 등): 방마다 `"rect": {"x":0,"y":0,"w":4,"h":3.5}`. **한 층 안에서는 모든 방에 rect 를 쓰거나 모두 빼야 한다.**
  - 방끼리 겹치지 않고 외곽 안에 들어가야 한다. 벽 두께는 무시하고 벽 중심선 기준으로 쓴다.
- 문 `doors`·창 `windows` 는 비워 두면 코드가 놓는다 (복도·거실에서 각 방으로, 묶음은 안방을 거쳐, 트인 방 사이는 문 없음, 거주 공간은 외벽 창). 꼭 정하려면:
  - 문: `{"room": "bed2", "to": "hall"}` (to = 이웃 방 id 또는 "outside"). 적은 문은 '꼭 이웃'으로도 지켜진다.
  - 창: `{"room": "living", "side": "S", "width": 2.4}`
- 여러 층이면 계단(`type: stair`)이 모든 층의 같은 rect 에 있어야 한다. 층을 추가할 때는 아래층 계단 rect 를 그대로 복사하거나 새 층을 rect 없이 쓴다 (코드가 같은 자리에 둔다).

## 4. 코드가 검사하는 것 (하네스 — 오류는 고쳐야 통과, 경고는 검토)
- 기본: 겹침·외곽 이탈·목표 면적 ±20%·문으로 모든 방에 도달·층간 계단·최소 치수
  (침실 7㎡·폭 2.4m, 거실 10㎡·폭 3.0m, 주방 4㎡·폭 1.8m, 욕실 2.5㎡·폭 1.2m, 복도·계단 폭 0.9m 이상)
- 장단변비(긴 변 ÷ 짧은 변): 침실 1.6 · 거실·식당·욕실·사우나 2.0 · 주방·드레스룸·다용도실 2.5 · 현관·수영장 3.0 이하 (넘으면 경고, 1.25배를 넘으면 오류)
- 복도: 바닥의 10% 초과 경고·15% 초과 오류, 일자 복도 12m 초과 경고·18m 초과 오류 · 복도 조각이 나란히 붙거나 여러 토막으로 끊기면 경고
  (코드는 복도를 한 줄기 + 가지 하나까지만 만들고, 일렬로 이어진 조각은 합친다)
- 외곽 효율: 실내 바닥 ÷ 외접 사각형 85% 미만이면 경고, 요청하지 않은 빈 곳(꺾인 외곽의 안쪽·둘러싸인 빈 곳)이 15㎡ 를 넘으면 오류
- 이웃: `adjacent`·`open_to`·`suite` 로 쓴 관계를 어기면 오류 (기본값은 경고)
- 채광: 거실·침실·서재가 외벽(또는 중정)에 닿지 않으면 오류 · 물 쓰는 곳이 세 곳 이상으로 흩어지면 경고
- 하네스·근거 자료에 '설계 지표'(외곽 효율·빈 곳·복도 %·복도 조각/줄기·최대 장단변비·이웃·채광·물 쓰는 곳 묶음 수)가 나온다 — 본문의 수치는 이 값을 쓴다.

## 5. 좋은 평면의 기준 (검토 때 확인)
- 구역: 현관 → 공용(거실·식당·주방) → (짧은 복도·홀) → 개인(침실). 공용과 개인을 섞지 않는다.
- 동선: 복도는 짧게(바닥의 5~12%), 현관에서 이어지는 한 줄기로 — 짧은 복도 여러 개 대신 거실·홀을 중심으로 방을 모은다. 욕실은 복도·홀에서 바로.
- 외곽: 요청하지 않은 빈 마당을 만들지 않는다. 큰 집이라고 ㄱ·ㄷ자로 꺾지 말고 일자형 안에서 공용·개인 구역을 나눈다.
- 채광: 거실·안방은 남쪽 외벽, 모든 침실은 외벽 창. 욕실·다용도실·드레스룸은 안쪽이어도 된다.
- 프라이버시: 현관에서 침실 문이 바로 보이지 않게, 손님방은 공용 공간 가까이, 안방은 드레스룸·욕실과 묶음으로.
- 물 쓰는 곳(욕실·다용도실·사우나)은 모은다. 주방은 식당과 붙이고(LDK 면 open_to), 다용도실은 주방 옆.

## 6. 답변 형식
- 본문: 요약(해석·가정 포함) → 층별 방 구성표(방·면적·구역) → 설계 의도(구역·동선·채광·프라이버시, 외곽 유형을 고른 이유). 코드가 계산한 면적·지표가 근거 자료·하네스에 있으면 그 숫자를 쓴다.
- **맨 마지막에 레이아웃 JSON 을 ```json 블록 하나로** 쓴다 (설명용 JSON 블록을 따로 만들지 않는다).
- 차장·부장·팀장은 고친 답변을 낼 때도 반드시 전체 JSON 블록을 다시 포함한다. (대리는 해석·가정과 방 프로그램표까지만)
- 수정 업무: 근거 자료의 '첨부 도면의 레이아웃 JSON' 을 복사해 요청한 부분만 바꾼다. 요청하지 않은 방의 rect 는 건드리지 않는다.
- 이 도면은 개념·참고용이다. 허가·시공 도면이 아님을 밝히고, 법규(건폐율·용적률·일조·피난)는 확인 필요로 남긴다.
