# 🏢 Agent Office

사용자는 **supervisor(팀장)** 에게 일을 맡기고, supervisor 가 질문을 보고 필요한 **전문가 에이전트**들에게 업무를 나눠 주는
조직도(트리) 구조의 멀티 에이전트 프레임워크입니다. 결과는 아래에서 위로 검토·통합되고, 사람이 최종안을 채택하면
참여한 모든 에이전트가 교훈을 받아 다음 업무에 반영합니다.

```
                👤 사용자  ⟷  [팀장] supervisor
                              /            \
                    [부장·리서치]        [부장·실행]
                         |                    |
                    [차장·분석]          [대리·실행안]
                     /       \                |
           [대리·팩트체크] [사원·초안]     [사원·사례]

  ① 요청 정리   질문 → '최종 상태 정의(목표·완료 기준·제약·형식)' 브리프
  ② 자료 조사   데이터 툴 + 웹 검색(동시에) → 모든 에이전트가 근거 자료로 사용 (출처 [번호] 표시)
  ③ 위 → 아래  관리자가 필요한 하위 전문가를 골라 업무 분배 → 맡은 하위들이 동시에 일을 시작
  ④ 맨 아래    실무자가 초안 작성 (+ 하네스: 코드·쿼리 결정론적 검증, 실패 시 재작성)
  ⑤ 아래 → 위  관리자가 하위가 모두 끝나면 적대적 리뷰어로 검토(1명)·통합(여러 명) (+ 비평가 채점, 불합격 시 자가 교정)
  ⑥ 👤 결정    사람이 채택(수정 가능)/반려 → 에이전트별 교훈 저장 → 다음 실행 프롬프트에 주입
```

### 팀 · 부서 · 층 (🏠 메인 = 📮 접수 창구 + 🏙 픽셀 빌딩 + 🗂 층별 부서 안내)

팀은 부서로 묶여 빌딩의 층에 들어갑니다 (`config/departments.yaml`). 1층은 로비(🛎 인포메이션 센터 · 👤 사용자 · 📰 신문 가판대 · 🤖 승인 데스크 · 💰 관리실).
일은 **부서장 중심**으로 맡깁니다: 🛎 인포메이션 센터(어느 부서 일인지 모를 때) → 👔 부서장(부서 안에서 팀 배정) → 팀장(팀원에게 분배).
업무 화면도 **부서 단위**입니다 (🏢 부서 업무): 부서를 고르면 그 부서의 부서원 전원이 사무실 하나에 있고(부서장실·회의실·자료실은 부서에 하나씩),
기본 입력은 '👔 부서장에게 맡기기', 팀 업무 양식은 '📋 부서 업무 목록'(팀별로 묶음)에서 직접 고릅니다.

## 2-1. 무료 모델 (FreeLLMAPI) — 유료 키를 쓸 수 없을 때

**FreeLLMAPI**([저장소](https://github.com/tashfeenahmed/freellmapi), Google·Groq 등 무료 티어를 OpenAI 호환 주소 하나로 묶는 내 PC 의 프록시)를
`freellm` provider 로 연결했습니다. 직급마다 유료 후보가 모두 실패(키 없음·크레딧 부족·장애)하면 무료 모델로 넘어가고,
사이드바의 **🆓 무료 모델만 사용** 을 켜면 처음부터 무료 모델만 씁니다.

**새 PC 설치는 [docs/FREELLM_설치.md](docs/FREELLM_설치.md)** — 맨 앞 **0절 '어느 방식으로 설치할까'** 에서 고릅니다.

| | A. 데스크톱 앱 (.exe, Docker 없이) | B. Docker |
|---|---|---|
| 이런 PC | 회사 PC(Docker 구독 없음) · RAM 8GB 이하 · 관리자 권한/재부팅 어려움 | 개인 PC 또는 Docker 구독 있음 · RAM 넉넉 · 늘 켜 두는 서버 |
| 준비물 | 설치 파일 하나 (Windows 10 이상 x64) | Docker Desktop + WSL 2 (관리자 권한·재부팅, 사양은 안내서 'B 방식 필요 사양') |
| `.env` 주소 `FREELLMAPI_BASE_URL` | `http://127.0.0.1:31415/v1` | `http://127.0.0.1:3001/v1` (기본값) |
| 통합 키 복사 | 트레이 → Copy Key | 대시보드 Keys 페이지 위쪽 |

공통 순서: 설치·실행 → 대시보드 Keys 페이지에 Google AI Studio·Groq 무료 키 등록 → **이 PC 의** 통합 키를 이 폴더 `.env` 의 `FREELLMAPI_API_KEY` 에 넣고 저장 → Streamlit 다시 켜기.
**다른 PC 의 `.env` 를 그대로 가져오면 통합 키·포트가 달라 401 이 납니다** (통합 키는 PC 마다 다름).

- 점검: `python scripts/check_freellm.py` (서버 켜짐·통합 키·`models.yaml` 의 무료 모델이 있는지, 키 값은 출력 안 함). 사이드바 ⚙️ 모델·검증 상태에 `✅ freellm` 이면 준비 완료.
- 평소: A 는 트레이 'Start at login', B 는 Docker Desktop 만 켜면 자동으로 다시 켜집니다 (`restart: unless-stopped`). 평가도 `python -m evals.run_eval … --free`

| 사원 | gpt-oss-20b → gemini-3.1-flash-lite → gemini-3.5-flash-lite | 가장 많이 호출되는 직급 → 하루 1,000회·0.5초로 가장 빠른 Groq gpt-oss-20b. 긴 프롬프트(분당 8천 토큰 초과)는 문맥이 큰 Flash-Lite 로 |
| 대리 | gemini-3.5-flash-lite → gpt-oss-120b → gemini-3.1-flash-lite | 검토(구조화 출력)가 빠르고 안정적(0.8초, 두 방식 모두 성공). 지능 순위 63 |
| 차장 | gpt-oss-120b → gemini-3.5-flash → gemini-3.1-flash-lite | 추론형 120B, 하루 1,000회라 여러 번 쓰는 실무 분석에 적합. 긴 입력은 Gemini 로 |
| 부장 | gemini-3.6-flash → gemini-3.5-flash → gpt-oss-120b | 하위 결과를 모아 통합 → 긴 입력(분당 25만 토큰)·지능 순위 39·5~7초 |
| 팀장 | gemini-3.7-flash → gemini-3.8-flash → gemini-3.6-flash → gpt-oss-120b | 최종 품질 담당·호출 수가 가장 적음 → 동작이 확인된 최상위 모델(순위 29, 37~52초로 느림). 3.8 은 순위 25 이지만 실측 시 시간 초과 |
| 보조 작업 | gpt-oss-120b → gemini-3.1-flash-lite | 브리프·검색어·비평·교훈 — 호출이 많아 하루 1,000회 한도가 필요 |

- **제외한 무료 모델**: qwen3.8-27b(분당 1천 토큰 — 긴 프롬프트 불가), gemma-4(3만 토큰 문맥·느림·구조화 출력 실패), gemini-2.5 계열(404), auto(자동 선택 — 응답 형식 오류).
- **한도 주의**: Gemini 무료 모델은 **모델마다 하루 20회·분당 10회**, Groq gpt-oss 는 **분당 8천 토큰**이라 하루 실행 횟수가 적습니다.
  곧 풀리는 한도(150초 이내, 예: 분당 토큰)는 그만큼 기다렸다 같은 모델로 다시 하고, 하루 한도가 찬 모델은 10분 동안 건너뜁니다.
  직급마다 Google(Gemini)과 Groq(gpt-oss)를 섞어 둔 것은 실측 중 Gemini 가 503 '요청 폭주'로 동시에 막힌 적이 있기 때문입니다.
- **동시 호출 제한**: 형제 에이전트가 동시에 일하므로 `config/settings.yaml` 의 `llm_concurrency` 로 provider 별 동시 LLM 호출 수를 제한합니다
  (기본 freellm 2 · google 3 · openai 4 · 그 밖 4, 0 이하 = 제한 없음). 무료 한도(429)가 자주 걸리면 freellm 을 1 로 낮추세요.
- 무료 티어 입력은 제공자 학습에 쓰일 수 있습니다 — 회사·개인 민감 데이터에는 유료 키를 쓰세요.

## 2-2. Claude 구독 (`claude_cli`) — 팀장이 API 크레딧 대신 구독으로 Claude Opus 5.5 사용

Anthropic API 키는 크레딧이 없어 꺼 두었지만, 이 PC 에 **Claude 구독(Pro/Max)** 으로 로그인한 Claude Code CLI 가 있으면
팀장이 `claude -p`(비대화형 실행)로 **Claude Opus 5.5** 를 씁니다. API 요금이 아니라 구독 사용 한도에서 차감되므로 메인 화면(🏠)에는
비용 0, 요금 칸 **'구독 (청구 없음)'** 으로 보입니다 (참고로 'API 로 했다면 얼마'인지 가격표 기준 추정치를 함께 보여 줌).

**어떻게 동작하나** (`core/claude_cli.py`)
- 호출 1회 = `claude -p` 프로세스 1개. 시스템 프롬프트는 `--system-prompt-file`(Claude Code 기본 프롬프트를 통째로 바꿈), 질문은 표준 입력으로 보냅니다.
- **답만 하게 잠금**: `--tools ""`(도구 전부 끔), `--safe-mode`(CLAUDE.md·hooks·플러그인·MCP·스킬 끔), `--strict-mcp-config`,
  `--permission-mode dontAsk`, `--permission-prompts none`, `--disable-slash-commands`, `--no-session-persistence`, 매번 새 빈 임시 폴더에서 실행.
  → `~/.claude` 의 hooks·설정이 명령을 실행하지 못합니다 (회사 관리 정책(managed settings)만 그대로 적용).
- `--bare` 는 쓰지 않습니다 — bare 모드는 구독 로그인을 읽지 않고 API 키만 씁니다.
- 자식 프로세스 환경에서 `ANTHROPIC_API_KEY` 등을 지웁니다 — `.env` 의 API 키(크레딧 없음)로 청구되지 않게.
- 초안은 `stream-json` 의 글자 조각으로 화면에 실시간 표시, 분배·검토(구조화 출력)는 `--json-schema` → `structured_output`.
- 실패 처리: CLI 없음·로그인 안 됨 → 바로 다음 후보(그 뒤 5분간 후보에서 빠짐) / **구독 한도** → 다음 후보로, 30분 동안 건너뜀 /
  과부하 → 잠깐 뒤 재시도 / 시간 초과(`settings.yaml` 의 `claude_cli.timeout_sec`, 기본 600초) → 다음 후보 /
  **안전 필터 거부**(`Opus 5.5's safeguards flagged this message`) → 다시 보내지 않고 다음 후보로, **그 팀에서만** 30분 동안 건너뜀
  (거부는 팀 스킬·프롬프트 내용 탓이라 같은 실행의 다음 단계가 또 거부를 기다리지 않게 — 다른 팀은 그대로 구독 Claude 사용).
- 대안 모델로 넘어가면 화면에 이유가 보입니다: 단계 줄 `⚠️ 대안 모델 — claude_cli · claude-opus-5-5: 안전 필터가 요청을 거부`,
  조직도 칸 `⚠️ claude-opus-5-5 건너뜀(안전 필터가 요청을 거부) → gpt-5.4` (자세한 오류는 '검증 기록'의 '건너뛴 모델').
- 사용량: 성공한 구독 호출만 🏠 사용량에 `claude_cli`(구독, 비용 0)로 팀·실행·팀원과 함께 기록됩니다. 거부·한도·시간 초과로 실패한 호출은 답이 없으므로 기록되지 않습니다
  — 사용량 표에 `claude_cli` 줄이 하나도 없으면 '구독이 한 번도 성공하지 못했다'는 뜻이니 단계의 '⚠️ 대안 모델' 이유를 보세요.
- 팀장 순서: **claude_cli Opus 5.5 → OpenAI gpt-5.5 → gpt-5.4 → (Anthropic API, 비활성) → 무료 모델**. 다른 직급은 그대로입니다.

**준비 (새 PC 에서 이 순서대로)**

> **데스크톱 앱(또는 그 안의 Code 탭)에 로그인돼 있어도 이 앱에서는 '연결 안 됨'으로 나옵니다.**
> Code 탭의 Claude Code 는 데스크톱 앱의 로그인을 그때그때 넘겨받아 쓸 뿐 CLI 로그인 파일을 만들지 않고,
> 이 앱이 띄우는 `claude -p` 는 **CLI 쪽 로그인(`~/.claude/.credentials.json` 의 `claudeAiOauth`)만** 봅니다.
> 그래서 아래 2번(`auth login`)을 PC 마다 한 번 해야 합니다.

1. **claude.exe 위치 확인** — 앱(`core/claude_cli.py` 의 `find_executable()`)은 아래 순서로 찾고, 먼저 찾은 것을 씁니다.

   | 순서 | 위치 | 언제 |
   |---|---|---|
   | ① | `.env` 의 `CLAUDE_CLI_PATH` | 직접 지정 (아래 위치에 없을 때만 넣기 — 데스크톱 앱 경로는 업데이트마다 바뀌므로 넣지 않는 것이 좋음) |
   | ② | PATH 의 `claude` | `npm i -g @anthropic-ai/claude-code` 등으로 설치 |
   | ③ | `~/.local/bin/claude.exe` | 공식 설치 스크립트(native) 로 설치 |
   | ④ | 데스크톱 앱이 함께 설치한 CLI (여러 버전이면 가장 최근 것) | 데스크톱 앱만 설치한 PC |

   ④ 의 실제 위치는 데스크톱 앱 설치 방식마다 다릅니다.
   - 일반 설치: `%LOCALAPPDATA%\Claude-Data\…\claude-code\<버전>\<해시>\claude.exe`
   - **Microsoft Store(MSIX) 설치**: `%LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude\claude-code\<버전>\<해시>\claude.exe`
     — 데스크톱 앱 안(Code 탭)에서는 `%APPDATA%\Claude\claude-code\…` 로 보이지만 **그 경로는 일반 PowerShell 에서는 없다고 나옵니다**
     (스토어 앱의 AppData 가상화). 앱 밖에서는 반드시 `Packages\…\LocalCache` 경로를 쓰세요.

   PowerShell 에서 이 PC 의 claude.exe 찾기 (②·③ 이 없을 때):
   ```powershell
   $claude = (Get-ChildItem "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe",
                            "$env:LOCALAPPDATA\Claude-Data\*\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue |
              Sort-Object LastWriteTime | Select-Object -Last 1).FullName
   $claude
   ```
   (PATH 에 `claude` 가 있으면 아래 `& $claude` 대신 `claude` 로 쓰면 됩니다.)

2. **CLI 로그인** — **일반 PowerShell 창**에서 (Code 탭 안의 터미널이 아니라 시작 메뉴의 PowerShell):
   ```powershell
   & $claude auth login
   ```
   - 기본이 구독(`--claudeai`) 로그인입니다. `--console` 은 API 과금이라 쓰지 않습니다. 회사 계정이 SSO 면 `--sso` 를 붙입니다.
   - 브라우저에서 구독 계정으로 로그인 → **Authorize**.
   - 브라우저가 안 열리거나 회사 PC 에서 '브라우저를 확인할 수 없습니다'가 나오면: 터미널에 나온 주소를 휴대폰(회사망 밖)에서 열어 승인 →
     화면의 **코드를 터미널에 붙여 넣고 Enter** (이걸 빠뜨리면 로그인이 저장되지 않음).

3. **확인**
   ```powershell
   & $claude auth status
   ```
   `"loggedIn": true`, `"authMethod": "claude.ai"` 면 성공. `false` / `"none"` 이면 2번이 끝나지 않은 것입니다.

4. **Streamlit 재시작** — 켜 둔 터미널에서 Ctrl+C → `streamlit run app.py`.
   (`.env` 는 시작할 때만 읽고, 로그인 상태는 5분 동안 캐시하므로 로그인·`.env` 를 바꾼 뒤에는 다시 켜는 것이 빠릅니다.)

5. 사이드바 ⚙️ 모델 상태에 `✅ claude_cli` 가 보이면 준비 완료.

**연결 안 됨 — 상태별 원인**

| 화면 표시 | 뜻 | 확인할 것 |
|---|---|---|
| `⚪ Claude CLI 없음` (`not_installed`) | 1번 표의 어디에서도 claude.exe 를 못 찾음 | 1번 찾기 명령 결과가 비었는지. 비었으면 데스크톱 앱 설치 또는 CLI 설치, 다른 위치면 `.env` 에 `CLAUDE_CLI_PATH` |
| `🔑 로그인 필요` (`logged_out`) | exe 는 찾았지만 `auth status` 가 `loggedIn: false` | 2·3번. 데스크톱 앱 로그인만으로는 안 됨 |
| `⛔ 비활성` (`disabled`) | `config/models.yaml` 의 `disabled_providers` 에 `claude_cli` 가 있거나 '🆓 무료 모델만 사용' 이 켜짐 | 설정 |
| 로그인했는데도 그대로 | 앱이 예전 상태를 기억 중 | 4번(재시작) |

앱이 실제로 찾는 exe 와 상태를 바로 보려면 (Agent_office 폴더, 가상환경에서):
```powershell
python -c "from core import claude_cli as c; print(c.find_executable()); print(c.cli_status())"
```

**주의**
- **구독 한도는 내가 직접 쓰는 Claude 대화·Claude Code 와 함께 줄어듭니다.** 그래서 호출 수가 적은 팀장(실행당 분배·검토·통합 몇 번)에만 배정했고,
  `llm_concurrency.claude_cli: 1` 로 한 번에 하나씩만 부릅니다. 한도에 걸리면 자동으로 GPT-5.5 로 넘어갑니다.
- 호출마다 CLI 를 새로 띄우므로 **시작에만 5~8초**가 더 걸립니다 (2026-10-22 실측: 한 문장 답변 — 첫 글자 9.1초, 전체 12.6초, 그중 모델 시간 4.4초 / 팀장 업무 분배(구조화 출력 Delegation) — 14초, 입력 1,572·출력 511 토큰, 대안 전환 없이 성공). 더 빠르게(한도도 덜 쓰게) 하려면 `settings.yaml` 의 `claude_cli.effort` 를 `medium`/`low` 로.
- '🆓 무료 모델만 사용' 을 켜면 claude_cli 도 쓰지 않습니다.

**되돌리기 (팀장을 다시 GPT-5.5 로)**: `config/models.yaml` 의 `disabled_providers` 에 `claude_cli` 를 추가하거나(`[anthropic, claude_cli]`),
팀장 `primary` 를 주석에 적힌 `{ provider: openai, model: gpt-5.5 }` 로 바꾸고 fallback 의 첫 줄(gpt-5.5)을 지우면 됩니다.

## 3. 설치 — 새 PC 에서 처음 시작하기

코드는 GitHub `jeong-yun/Project` 저장소의 `LLM/Agent_office` 폴더에 있습니다. 아래는 Windows PowerShell 기준입니다.

```powershell
# 1) 저장소 내려받기 (원하는 폴더에서)
git clone https://github.com/jeong-yun/Project.git
cd Project\LLM\Agent_office

# 2) 가상환경 만들기 → 켜기 (Python 3.11 이상)
python -m venv .venv
.venv\Scripts\Activate.ps1
#   macOS / Linux:  python3 -m venv .venv  →  source .venv/bin/activate

# 3) 패키지 설치
python -m pip install --upgrade pip
pip install -r requirements.txt

# 4) API 키 설정: .env.example 을 .env 로 복사한 뒤 메모장에서 키 입력
Copy-Item .env.example .env
notepad .env
#   macOS / Linux:  cp .env.example .env

# 5) 실행 → 브라우저에서 http://localhost:8501
streamlit run app.py
```

> `.env` 는 이 폴더 안의 것을 우선 읽고, 없는 값은 바로 위 폴더의 `.env` 에서 보충합니다.
> **`.env` 는 절대 git 에 올리지 않습니다** — `.gitignore` 에 들어 있고, 저장소에는 값이 빈 `.env.example` 만 올립니다.
> 잘 설치됐는지 확인하려면 `pip install -r requirements-dev.txt` 후 `python -m pytest -q` (API 키 없이 실행, 모두 passed 면 정상).

### git 으로 옮겨지지 않는 것 (직접 챙기기)

| 항목 | 내용 | 다른 PC 로 옮기는 방법 |
|---|---|---|
| `.env` | API 키 | 새로 만들어 키 입력 (메신저·메일로 키 파일을 보내지 않는 것을 권장) |

| `.venv/` | 가상환경 | 옮기지 말고 PC 마다 새로 만들기 (2~3단계) |

## 5. 화면 보는 법

왼쪽 위 **화면**에서 🏠 메인 / 🏢 부서 업무를 고릅니다 (주소 `?view=home|dept&dept=<부서 id>`, 처음에는 🏠 메인).
예전 주소 `?view=team&team=<팀 id>` 도 그대로 열립니다 — 그 팀이 있는 부서 업무 화면으로, 그 팀을 '지금 보는 팀'으로.

🏠 메인은 위에서부터 **📮 접수 창구 → 🏙 픽셀 빌딩 → 🗂 층별 부서 안내 → 🎛 부서별 모델 선택 → 아래 섹션**입니다.

**📮 접수 창구 — 🛎 인포메이션 센터 (`reception_ui.py` · `building_ui.py` · `core/reception.py`)**

입력창은 메인에 하나(🛎 인포메이션 센터), 부서 화면에 하나(👔 부서장 창구)만 둡니다 — 같은 입력창이 두 군데 있어 헷갈리지 않게.
부서를 알면 창구의 부서 버튼(🔬 리서치·지식부 … 👔 커리어부)·빌딩의 부서 띠·아래 안내의 '🏢 ○○부 사무실로'를 누르면 그 부서 업무 화면의 부서장 창구가 열립니다.

```
🛎 인포메이션 센터   질문 → 👔 부서장 회의 (보조 모델 1회로 모든 부서를 한꺼번에) → 부서마다 ✅/❌ · 맞는 정도(0~10) · 한 줄 판단 표
                    ├ 맡을 부서가 있음 → [👔 ○○부 부서장에게 넘기기] (또는 다른 부서로) → 그 부서 업무 화면이 열리고 부서장이 곧바로 팀 배정
                    └ 없음 → "이 일을 할 부서가 없습니다. 새 부서를 만들까요?" + 제안(부서·팀 이름, 하는 일, 팀 구성, 필요한 도구)
                         ├ [🆕 만들기] → 파일 미리 보기(고칠 수 있음) → [✅ 확인하고 저장] 을 눌러야 저장 → "원래 질문을 새 부서로 넘길까요?"
                         └ [🗂 나중에] → 🗂 추후 진행 목록 (data/new_dept_later.json) — 나중에 [만들기] 로 다시 꺼냄
👔 ○○부 부서장       (🏢 부서 업무 화면 — 아래 '🏢 부서 업무' 참고) 요청 → 부서장이 하위 팀 하나를 고르고 범위를 확인
                    → [▶ 바로 맡기기] 그 팀의 팀장이 곧바로 시작 — 진행·결과·결정은 같은 부서 화면에서
```

- **부서장 회의를 모델 1회로 하는 이유**: 부서장마다 따로 부르면 부서 6개 = 호출 6회·대기 6번이고, 서로의 판단을 모릅니다.
  한 번의 구조화 출력(`MeetingResult`: 분석 → 부서마다 할 수 있음·맞는 정도·이유 → 맡길 부서)에 부서마다 부장 이름·관점(persona)·소속 팀·다루는/다루지 않는 질문을 넣으면
  호출 1회로 부서끼리 비교해 고를 수 있습니다. 모델이 고른 부서는 그대로 믿지 않고 코드가 다시 확인합니다 (목록에 있고 `할 수 있음`이고 맞는 정도 5 이상 중 가장 높은 곳).
- **모델을 못 쓰면**(키 없음·한도) 낱말 비교: 팀 `scope.keywords` 가 가장 많이 맞는 부서. 아무것도 안 맞으면 기본 팀(범용 창구)의 부서로 — 모델 없이는 '맡을 부서 없음'을 단정하지 않습니다.
- **범용 기본 팀**은 일반 지식으로 끝나는 조사·정리만 맡는 것으로 회의에 소개합니다 → 세무 신고서·계약 법률 검토처럼 꾸준한 전문 업무는 '맡을 부서 없음'으로 새 부서 제안.
- **모델**: 부서장 창구 = '🎛 부서별 모델 선택'에서 그 부서에 고른 부장 모델 (없으면 `models.yaml` 의 `critic` → `utility`). 인포메이션 센터·새 부서 제안 = 기본(`critic` → `utility`). 화면에 실제로 쓴 모델을 보여 줍니다.
- **🆕 새 부서 만들기** (`core/dept_builder.py`)
  - 초안: `config/departments.yaml` 에 넣을 부서 항목(id·이름·이모지·안 쓰는 색·소개·팀·👔 부장 이름·관점) + `teams/<새 팀>/team.yaml` (`teams/_template/team.yaml` 바탕 — 조직도·페르소나 칸·scope·검토 기준·처음 질문을 자유 질문 예시로).
  - **도구는 비워 둡니다** (`tools: []`) — 웹 검색처럼 밖으로 나가는 도구는 '필요한 도구' 주석으로만 적고, 사람이 확인한 뒤 직접 켭니다.
  - 저장 전 검사: YAML 문법 · id 모양(영문 소문자·숫자·밑줄) · 기존 부서·팀과 겹침 · 팀 형식(`core/schemas.Team`) · 직급·툴·검증기(`validate_config`). 문제가 있으면 저장하지 않고 이유를 보여 줍니다.
  - 저장: 새 `team.yaml` + `departments.yaml` 의 `other:` 앞에 부서 항목 (위쪽 설명 주석은 그대로). 다시 읽어 확인이 안 되면 둘 다 되돌립니다. 저장하면 빌딩에 새 방(필요하면 새 층)이 바로 생깁니다.
  - 기록: 자율 실행과 같은 해시 체인 감사 로그(`data/autonomy/audit.jsonl`)에 `dept_created`·`dept_deferred` 한 줄 (결정한 사람 user, 경로 info_center).
- **🖥️ 커맨드 센터 터미널**의 '그 밖의 한 줄'도 자유 질문과 같은 범위 확인을 거칩니다 → 범위 밖이면 맡기지 않고 '🚫 … ◇◇팀이 맞습니다' + **➡️ ◇◇팀에 맡기기** 버튼 (누르면 그 팀이 바로 시작).

**🏙 픽셀 빌딩 (`building_ui.py` · `core/building.py` · `office_component/building.js`)**

```

              부서 띠(부서 색) = 부서 이름 · 👔 부장 · N팀 M명 · ● 일하는 팀 수

                 🛠 팀원     팀원마다 지금 쓸 모델 · 최근 7일 호출·토큰·추정 비용 · 교훈 수
```

- 파이썬은 1초마다 '지금 상태' 스냅샷(배치·말풍선·가야 할 자리·최근 쪽지 16개)만 보냅니다. 걷기·쪽지 날리기는 브라우저 캔버스가 스스로 그리므로
  화면을 다시 그려도 움직임이 끊기지 않고 서버 쪽 비용이 거의 늘지 않습니다 (iframe 을 새로 만들지 않는 양방향 컴포넌트, `office_component/index.html`).
- 그림은 모두 코드로 그린 것입니다 — 외부 이미지·라이브러리·CDN 없음 (`office_component/ASSETS.md`).
- 커맨드 센터는 고른 탭 하나만 그립니다 (저장소 조회는 그 탭을 열었을 때만).

## 5-1. 사용법 — 좋은 질문은 '과정'이 아니라 '최종 상태'를 정의한다

| | 예시 |
|---|---|
| ❌ 과정 지시 | "1) HBF 검색하고 2) 정리한 다음 3) 표로 만들어줘" |
| ✅ 최종 상태 정의 | **목표** 팀 회의에서 5분 안에 공유할 HBF 설명 자료 / **완료 기준** 정식 명칭·정의, HBM 과 비교 표, 사실마다 출처 / **제약** 비전공자용, A4 1장 / **형식** 요약 → 비교 표 → 핵심 3개 → 출처 |

- 화면의 **💡 질문 예시**를 고르면 질문과 최종 상태가 채워집니다. 예시는 **그 팀 분야 것만** 보입니다 (팀마다 3개, `team.yaml` 의 `free_examples`).
- **🎯 원하는 최종 상태**를 비워 두면 보조 모델이 질문에서 목표·완료 기준을 추론해 채웁니다 (`🤖 빈 항목은 AI 가 정리`).
- **완료 기준**은 검토자·비평가의 채점 기준이 됩니다 → "정식 명칭과 출처를 제시한다"처럼 검증 가능한 문장으로 쓰세요.
- 과정(누가 무엇을 조사할지)은 supervisor 가 스스로 나눕니다.
- 결과를 그대로 받아들이지 말고, 타임라인의 **검토·비평 기록**(취약점·논리 비약)을 확인한 뒤 채택하세요.
- **문의 대상**에서 다른 칸을 고르면 그 에이전트가 supervisor 가 되어 그 아래 팀만 일합니다 (비용·시간 절약).
- 주식·여행 팀은 **📋 업무 선택**에서 업무를 고르고 입력칸만 채우면 됩니다. 목표·완료 기준은 업무 양식에 미리 정의돼 있어
  자동으로 '최종 상태' 브리프가 됩니다 (예: 주가 전망 → "상승·기본·하락 시나리오와 확률, 기준일 인용").
- 모든 에이전트는 **오늘 날짜**를 기준으로 '현재·최근'을 판단하고, 주식 팀 뉴스 검색은 최근 1개월로 제한됩니다.

### 팀별 질문 범위 (💬 자유 질문) — 각 팀은 자기 분야 질문만 받는다

자유 질문은 맡긴 팀이 그대로 답하므로, 다른 분야 질문(예: 주식 팀에 여행 계획)은 엉뚱한 답이 나옵니다.
그래서 팀마다 `team.yaml` 에 `scope`(다루는 것·다루지 않는 것)를 두고, **맡기기 전에** 범위를 확인합니다 (`core/scope.py`).

| 팀 | 이 팀이 다루는 질문 |
|---|---|
| 기본 팀 | 무엇이든 — **범용 창구** (`scope.accept_all: true`, 범위 확인 없음) |
| 개념 편집 팀 | IT 개념(보안·AI·데이터 인프라) 용어·약어 뜻, 개념끼리 차이, 카탈로그 팩트체크 |
| 주식 팀 | 종목 판단·주가 전망·매매 전략·보유 종목 대응·포트폴리오, 실적·공시·증시 흐름 |
| 🚄 국내 여행팀 | 국내 여행 일정·동선(KTX·버스·렌터카)·숙소·맛집·축제 |
| 🌏 해외 여행팀 | 해외 여행 일정·항공·현지 교통·숙소, 비자/입국·환전·시차·로밍·보험 |
| 🎵 음악 팀 | 노래·반주 — 가사·곡 구성·장르·분위기, Lyria 프롬프트, 곡 편집 |
| 📐 설계 팀 | 집·건물 평면 — 방 배치·동선·채광·수납, 도면 수정·층 추가, 3D |
| 🛡️ 보안 거버넌스 팀 | ISMS-P·ISO 27001·NIST CSF 통제 해석, 증적·정책 미비점, 설정 drift |
| 🏗️ 인프라 보안 팀 | Terraform·쿠버네티스·Dockerfile 위험 설명과 수정안 |
| 👔 포트폴리오·자소서 팀 | 올린 경력 문서 기반 자소서·포트폴리오·면접 준비 |

- **화면**: 자유 질문 칸 위에 '🧭 이 팀이 다루는 질문: …'(❔ 에 다루는 것·다루지 않는 것), 🏙 빌딩 방 설명·📋 목록 카드에 '질문 범위'.
- **확인 순서** (자유 질문만 — 📋 업무 양식은 이미 그 팀 업무라 확인하지 않음)
  1. 낱말 확인 (모델 없음): 질문에 이 팀 `scope.keywords` 가 다른 어느 팀보다 많이 맞으면 바로 통과.
     직전 결과에 대한 짧은 후속 질문('이거 표로 다시 정리해줘')도 통과.
  2. 애매하면 **🧭 부서장 배정**(`core/building.route_request`, 보조 모델 1회)을 모든 팀 대상으로 불러 가장 알맞은 팀을 고릅니다.
     이 팀이면 통과. 모델을 못 쓰면(키 없음·한도) 다른 팀 낱말이 분명히 맞을 때만 막고, 아니면 그대로 받습니다.
- **범위 밖이면** 실행하지 않고 "이 질문은 ○○팀 범위가 아닙니다 — ◇◇팀(◇◇부)이 맞습니다" 와 함께
  **➡️ ◇◇팀으로 가서 질문하기**(그 팀 자유 질문 칸에 같은 질문을 채워 이동) · **✏️ 질문 고치기** 버튼을 보여 줍니다.
  '그래도 실행'은 두지 않습니다 — 각 팀은 자기 분야만 받습니다. 어디에 맞는지 모르겠으면 기본 팀(범용 창구)에 맡기면 됩니다.
- **🖥️ 커맨드 센터 터미널** 한 줄 업무도 같은 확인을 거칩니다 (범위 밖 → **➡️ ◇◇팀에 맡기기** 버튼). 👔 부서장이 배정해 '▶ 바로 맡기기'로 시작한 업무는 이미 배정된 것이라 다시 확인하지 않습니다.
- **💬 결정 전 문의**(결과에 대해 묻기·고치기)는 범위 확인을 하지 않습니다.
- 판단 기록: `data/scope_log.jsonl` (팀·질문·통과 여부·추천 팀·단계·이유) — 낱말·범위 문구를 다듬을 때 봅니다.
- 범위·예시 바꾸기: `teams/<팀>/team.yaml` 의 `scope`(summary·accepts·rejects·keywords·accept_all) 와 `free_examples` 를 고치면 다음 화면부터 반영.

## 5-2. 진행 확인·개입 — 느린 호출 보기 · 모델 바꾸기 · 고쳐 다시 · 단계마다 확인

진행 중인 업무가 오래 걸릴 때 **어느 모델 호출이 왜 느린지** 보고, 그 자리에서 손쓸 수 있습니다
(`run_control_ui.py` · `core/call_monitor.py` · `core/switch_rules.py` · `core/step_mode.py`).

**⏱ 무엇이 느린지 보기**
- 질문 상자 아래 한 줄: `⏱ 모델 호출 12번 · 진행 중 2 · ⚠️ 응답 없음 1 · 기다린 시간 40초 · 모델 시간 5분 10초`.
  응답(토큰)이 1분 넘게 없는 호출이 있으면 노란 경고로 '누가 · 무슨 일 · 어느 모델 · 몇 분째'를 보여 줍니다 (`settings.yaml` `call_monitor.stall_sec`).
- **⏱ 호출 모니터** 토글 → 탭 5개 (켜 둔 동안 1초마다 경과 시간이 늘어남)
  - ▶ 진행 중·조작: 지금 진행 중인 호출 한 줄씩 + 표시 — `⚠️ 응답 없음 N분` · `🔁 재시도 n회` · `↪️ 대안 모델로` · `⏳ 동시 호출 자리 대기` · `⏸ 5초 뒤 같은 모델로 다시`
  - 📊 시간표: 호출마다 가로 막대 (빗금 = 자리·재시도 대기, 색 = 모델이 답하는 시간, 빨강 = 실패·응답 없음, 보라 = 사람이 끊음)
  - 📋 전체 호출: 상태 · 누가 · 일(초안·검토·비평·하네스 재작성·요청 정리…) · 모델 · 경과 · 대기 · 모델 시간 · 첫 토큰까지 · 토큰
  - 🧮 요약: 단계별·모델별 시간, 가장 느린 호출 5개, 기다린 시간 vs 모델 시간
  - 🧑 개입 기록: 누가 · 무엇을 · 언제 (아래 개입이 모두 남음. 📜 전체 진행에도 함께 보임)
- 🖥️ 커맨드 센터 📈 모니터 탭에도 진행 중인 호출과 표시가 한 줄씩 나옵니다.
- 기록은 업무와 함께 저장되어 **🕘 지난 업무** 창의 '⏱ 호출 기록'에서 다시 볼 수 있습니다.

**⏭ 이 호출을 다른 모델로** — 느린 호출 줄의 `⏭ 바꾸기` → 모델 고르기 → `⏭ 이 호출 끊고 이 모델로 다시`
- 고를 수 있는 모델은 🎛 팀원 모델 선택과 같은 규칙입니다 — 상사보다 강한 모델 금지, 하위가 있는 관리자는 맨 아래 줄 금지,
  무료 모델을 쓰게 된 팀원은 무료 모델만, 맡길 때 '🆓 무료 모델만 사용'이었으면 유료 안 됨, 키 없음·비활성·서버 꺼짐 안 됨.
  안 되는 모델은 '🚫 고를 수 없는 모델과 이유'에 이유와 함께 나옵니다. 비평가·요청 정리 같은 공용 호출은 팀원 규칙을 받지 않습니다.
- `남은 업무에도 이 모델`을 켜면 이번 업무에서 같은 담당(예: 사원·사례, 비평가)의 다음 호출도 그 모델을 먼저 씁니다 (다음 업무에는 영향 없음).
- 끊긴 호출의 답은 버리고 그 단계만 새 모델로 다시 합니다. 모델 실패로 치지 않으므로 그 모델을 쉬게(쿨다운) 하지 않습니다.
- 고른 호출이 그 사이 끝나면 다른 호출로 저절로 옮기지 않고 '다시 고르세요'라고 알립니다 (누르려던 버튼이 엉뚱한 호출을 끊지 않게).

**바로 끊기지 않는 경우와 이유**
- `claude_cli`(구독): `claude -p` 프로세스를 바로 강제 종료합니다.
- 스트리밍 초안: 다음 조각에서 멈추고 스트림(HTTP 연결)을 닫습니다 — 바로 멈춤.
- 한 번에 받는 호출(검토·통합·비평·분배·요청 정리): 화면과 업무는 **바로** 다음으로 넘어가지만, 이미 보낸 HTTP 요청은
  뒤에서 응답이 올 때까지 기다렸다 버립니다 (LangChain 의 동기 호출은 중간에 취소할 수단이 없음). 그래서 **그 호출의 토큰은 청구될 수 있고**,
  그동안 provider 동시 호출 자리를 하나 더 쓰는 셈이 됩니다. 시간 제한이 없는 Gemini 호출도 같은 방식으로 '건너뛰기·바꾸기'가 됩니다.
- 데이터 툴(주가·여행 달력)·웹 검색·하네스 검사는 모델 호출이 아니라 끊을 대상이 아닙니다 (보통 몇 초).

**⛔ 건너뛰기 · ⏹ 중단**
- `⛔ 비평 건너뛰기`: 이번 업무의 비평가 채점·자가 교정을 건너뜀 (진행 중인 비평 호출도 끊음) → 지금 답변으로 진행.
- `⛔ 하네스 재시도 건너뛰기`: 하네스 실패 시의 재작성 반복을 그만두고 직전 답변으로 진행.
- `⏹ 지금까지 결과로 마무리`: 새 호출을 막고 진행 중인 호출을 끊은 뒤, 끝난 결과를 모아 supervisor 의 **부분 결과**로 결정 화면에 올립니다
  (채택·반려·✏️ 고쳐 다시 가능). 체크포인트는 그대로 남습니다.

**✏️ 질문·브리프 고쳐 다시** (결정 전 아래 접기 상자)
- 질문·최종 목표·완료 기준·제약·결과 형식을 고치고 다시 시작할 곳을 고릅니다.
  - `업무 분배부터 (자료 조사 결과 유지)`: 웹·데이터 조사 결과를 재사용하고 새 브리프로 분배부터 다시
  - `처음부터 (요청 정리 다시)`: 새 질문으로 브리프부터 다시 (브리프를 AI 가 다시 정리하거나, 고친 브리프를 그대로 씀)
- 진행 중이면 먼저 멈춘 뒤 LangGraph 체크포인트에서 갈래(fork)를 만들어 다시 합니다. 같은 업무 id 그대로라 결정·교훈도 이어집니다.
- 예전 시도는 지우지 않고 **🆚 이전 시도와 비교**에서 질문·목표·최종 답을 나란히 봅니다. 호출 기록에는 몇 번째 시도인지(`시도` 열)가 남습니다.

**🔀 단계마다 확인** (업무 맡기기 위의 토글, 기본 꺼짐 — 끄면 지금과 똑같이 한 번에 진행)
- 켜면 세 곳에서 멈추고 내 선택을 기다립니다 (사이드바 '🔀 확인 대기', 알림).
  1. **① 브리프·방향**: supervisor 가 서로 다른 방향 2~3개(예: A 기술 중심 / B 성과 중심 / C 리더십 중심)를 제안 → 하나를 고르거나 `✍️ 직접 쓰기`.
     브리프도 여기서 고칠 수 있습니다. 고른 방향은 브리프 제약 '진행 방향(사용자 선택)'으로 모든 팀원에게 전달됩니다.
  2. **② 업무 분배**: supervisor 가 하위에게 줄 업무를 고치거나, 맡기지 않을 하위를 뺍니다.
  3. **③ 초안 (통합 전)**: 실무자 초안을 직접 고치고, 통합할 때 참고할 지시(예: '성과 숫자 위주로, 표로')를 남깁니다.
- `▶ 이대로 진행`을 누르면 다음 단계로 갑니다 (고칠 것이 없으면 그대로 누르면 됨). 선택은 모두 🧑 개입 기록에 남습니다.
- 방향 제안에 모델 호출이 1번 더 듭니다. 멈춘 동안에는 비용이 들지 않습니다.

### 👔 부서 부장 = 비평가 · 🧭 부서장 (`core/dept_heads.py`)
부서마다 부장이 한 명 있습니다. 팀 조직도 안의 팀원이 아니라 **부서 전체를 보는 사람**이고, 일이 두 가지입니다 (팀 조직도는 그대로).

1. **⚖️ 비평가** — 그 부서 모든 팀의 최종 답변(검토 과정의 논리)을 채점하고, 불합격이면 자가 교정을 시킵니다.
   비평 프롬프트 맨 앞에 부장의 관점(`config/departments.yaml` 의 `head.persona`)이 들어갑니다.
2. **🧭 부서장** — 메인 화면에서 부서에 맡긴 요청을 알맞은 팀으로 보냅니다 (같은 부장 모델).

**비평가 모델 정하는 순서**

| 순서 | 출처 | 설명 |
|---|---|---|
| 1 | 화면에서 고른 부장 모델 | '🎛 부서별 모델 선택'의 👔 부장 칸 (데이터 폴더 `department_models.json`) |
| 2 | 팀장 모델 (비공개 팀만) | `team.yaml` 에 `private: true` 인 팀(👔 포트폴리오·자소서)은 부장 모델을 고르지 않았으면 팀장 모델 후보로 비평 — 이력서가 팀원이 쓰는 제공처 밖으로 나가지 않게 |
| 3 | `config/models.yaml` 의 `critic:` | 선택 항목 (주석 예시 있음). claude_cli 를 넣으면 비평마다 구독 한도를 함께 씀 |
| 4 | `config/models.yaml` 의 `utility` | 예전 동작 (아무것도 안 고르면 지금과 같음) |

- **대안 모델**: 고른 부장 모델이 안 되면 3·4 의 후보 중 **고른 모델보다 강하지 않은 것**만 씁니다 (대안으로 넘어가도 더 비싼 모델로 올라가지 않음). 무료(freellm) 모델을 고르면 대안도 무료만.
- **🆓 무료 모델만 사용**: 유료가 꺼지므로 후보 중 무료 모델이 비평합니다 (후보에 무료가 없으면 utility 의 무료 모델을 끝에 붙임).
- **강도 규칙 (결정)**: 부장 모델은 위아래 제한이 없습니다 — 비평가는 글을 쓰지 않고 채점만 하므로 빠르고 싼 모델도 고를 수 있게. 대신 비평가가 **채점 대상(팀장)보다 약한 모델**이면 화면과 검증 기록에 ⚠️ 로 알립니다 (약한 모델은 강한 모델의 실수를 놓치기 쉬움).
- **비공개 팀 (결정)**: 부장 모델을 골랐는데 그 제공처가 팀원들이 쓰는 제공처에 없으면 🔒 경고 ("문서 내용이 google 로도 보내집니다").
- **누가 비평했나**: 결과의 '검증 기록' 제목에 `⚖️ 비평 5/5 통과 · 🔬 리서치·지식부 부장 (gpt-5.4)`, 펼치면 `provider · model` 까지. 대안 모델로 넘어갔으면 검증 기록에 한 줄.
- **큰 입력**: 비평가에게는 하위 결과 모음을 `input_chars`(16,000자), 수정 답변을 `answer_chars`(24,000자, 앞 2/3·뒤 1/3 을 남기고 가운데 생략)까지만 넘깁니다 — 팀장 통합본이 4만 토큰이면 그대로 넘길 때 느리고 멈췄습니다 (2026-11-04 실측).

team.yaml `verification.critic` 으로 팀별 비평 설정을 덮어쓸 수 있습니다 (주식 팀: 모든 검토 단계 비평, 자가 교정 최대 2회, 점수-분석 불일치·근거 없는 수치 규칙).

업무 양식(team.yaml `tasks`)마다 `validators`·`harness_options` 를 따로 지정할 수 있습니다 (예: 주가 전망은 `required_terms: [기준일, 시나리오, 상승, 하락, 확률]`).

새 검증기(예: ClickHouse 테스트 DB 실행)는 `core/harness/validators.py` 에 `Validator` 를 상속한 클래스를 만들고 `@register` 를 붙이면 됩니다.

### 단계별 평가 실행

```bash
python -m evals.run_eval evals/cases/general.yaml   # 기본 팀 (HBF 등)
python -m evals.run_eval evals/cases/stock.yaml     # 주식 팀 (삼성전자 전망·보유 전략·판단·매매 전략)

```

케이스는 `question`(자유 질문) 또는 `task` + `inputs`(업무 양식) 로 쓰고, 단계는 `tools · research · plan · draft · review · integrate · final` 중에서 검사합니다.

케이스 작성법은 `evals/cases/general.yaml`, 보안 로그 분석(페이로드 복원 → 시그니처 매칭 → 위험도) 예시는 `evals/cases/_security_template.yaml` 참고.
결과는 화면 표와 `data/evals/<시각>.json` 으로 저장됩니다.

## 7. 커스터마이징

### 조직도 바꾸기 (전문가 추가)
`teams/<팀>/team.yaml` 의 `org` 에서 `children` 에 칸을 추가합니다. `rank`(직급 → 모델·기본 이미지), `specialty`(전문 분야) 를 지정합니다.
`org` 를 지우면 `config/ranks.yaml` 순서대로 팀장 → 부장 → 차장 → 대리 → 사원 한 줄 조직도가 자동으로 만들어집니다.

### 팀 스킬 (반복 업무 지침)
`teams/<팀>/skills/*.md` 에 지침을 쓰면 그 팀의 모든 에이전트 시스템 프롬프트에 들어갑니다 (예: `answer_style.md`, `adversarial_review.md`).
스킬은 사람이 쓰는 고정 지침, 교훈은 사람의 결정에서 자동으로 쌓이는 학습입니다.

스킬이 길면 실무자에게는 필요한 절만 줄 수 있습니다 — `org` 의 칸에 `skill_sections: ["[역할]", "[2단계"]` (줄 첫머리 `[…]` 절 제목의 앞부분, 코드 블록 안은 제외).
같은 칸에 `output_scope: "…"` 를 쓰면 그 실무자는 브리프의 완료 기준(팀 최종 답변 기준) 대신 그 범위만 씁니다.
팀에 `review_mode: edit` 를 쓰면 하위 1명 검토(review)가 전문을 다시 쓰지 않고 고칠 곳만 `찾을 문장 → 바꿀 문장`으로 고칩니다 (여러 명 통합은 그대로 전문). 예: 개념 편집 팀.

### 에이전트 이미지 바꾸기
**화면에서 바꾸기 (권장)**: 조직도에서 에이전트를 클릭 → 패널의 **🖼 이 에이전트 이미지 바꾸기** → 그림 올리기 → 💾 저장.
- 가운데를 정사각형으로 잘라 256×256 으로 저장하고, '작업 중' 그림을 따로 올리지 않으면 말풍선(…)을 붙여 자동으로 만듭니다.
- **↩ 기본 이미지로** 를 누르면 원래(직급 공용) 이미지로 돌아갑니다. png/jpg/webp, 5MB 이하.

**파일로 바꾸기** (먼저 찾은 것 사용):
1. `teams/<팀>/avatars/<에이전트id>.png` — 에이전트 한 명만 (예: `lead.png`) ← 화면에서 저장하면 이 위치
2. `teams/<팀>/avatars/<직급id>.png` — 그 팀의 해당 직급 전체
3. `assets/avatars/<직급id>.png` — 공용 기본 이미지
- 같은 이름에 `_working` 을 붙인 파일(예: `lead_working.png`)은 **답변·검토 중**일 때 표시됩니다.
- png/jpg/jpeg/webp, 정사각형 권장. 기본 이미지 다시 만들기: `python scripts/make_placeholder_avatars.py --force`
- 직급 id: `staff`(사원), `assistant_manager`(대리), `deputy_gm`(차장), `gm`(부장), `team_lead`(팀장)

### 모델 바꾸기
`config/models.yaml` 에서 직급별 `primary` / `fallback` 을 수정합니다. 특정 팀만 바꾸려면 team.yaml 의 `model_overrides`.
새 모델을 넣으면 같은 파일의 `model_tiers`(모델 강도 순서, 위가 가장 강함)의 알맞은 줄에도 넣는 것이 좋습니다.
빠뜨려도 앱은 멈추지 않고 이름으로 강도를 추정해 넣습니다 (사이드바 ⚙️ 모델·검증 상태에 '이름으로 강도를 추정한 모델'로 표시).
yaml 을 고치지 않고 새 모델을 쓰려면 아래 '새 모델 쓰기'를 보세요.
- **Gemini 시간 제한**: `config/settings.yaml` 의 `google.timeout_sec`(기본 180초). 넘으면 같은 모델로 1번 더 → 그래도 안 되면 대안 모델. langchain-google-genai 2.1 은 `timeout` 값을 받아도 요청에 넘기지 않아 구글 기본값 600초까지 멈췄습니다 → `core/llm_factory.py` 가 요청마다 직접 넣습니다.

### 새 모델 쓰기 — 자동으로 찾기 · 직접 입력 (yaml 안 고침)
각 사가 새 모델을 자주 내놓으므로, `config/models.yaml` 에 없는 모델도 **🎛 부서별 모델 선택** 에서 고를 수 있습니다 (`core/model_catalog.py`, 화면 `models_ui.py`).

- **자동으로 찾기 (목록 새로 고침)**
  - 앱을 켤 때 저장된 목록이 하루(24시간)보다 오래됐으면 **백그라운드로** 각 사 공식 모델 목록 API 를 부릅니다. 화면은 기다리지 않고, 실패해도 앱은 그대로입니다.
    - OpenAI `/v1/models` · Google Gemini `models.list` · Anthropic `/v1/models`(켜져 있을 때만) · Upstage `/v1/models` · FreeLLMAPI `/v1/models` · Claude 구독(`claude_cli`)은 목록 API 가 없어 CLI 가 받는 이름(`opus`·`sonnet`·`haiku` 별칭과 정식 이름).
    - 키가 있고 `disabled_providers` 에 없는 provider 만 부릅니다. 한 provider 에 6초까지만 기다립니다.
  - 대화 모델만 남깁니다 — 임베딩·음성(whisper·tts)·이미지(dall-e·imagen·nano-banana)·검열·파인튜닝(`ft:`)·실시간 모델은 뺍니다. Gemini 는 `generateContent` 를 지원하는 모델만.
    OpenAI 의 Responses API 전용(`*-pro`·`codex`)·옛 Completions 전용(`*-instruct`) 모델도 뺍니다 (앱은 Chat Completions 로 부름 — 꼭 써 보려면 직접 입력 → 🧪 연결 시험). 날짜가 붙은 고정판은 날짜 없는 이름이 있으면 뺍니다.
  - 결과는 데이터 폴더의 `model_catalog.json` 에 저장합니다. 네트워크·키가 없으면 → 저장된 목록 → 그것도 없으면 yaml 만 씁니다. 지금 다시 받으려면 **🔄 모델 목록 새로 고침** (사이드바 **🧩 모델 목록 · 직접 입력**, 또는 🎛 상자의 '➕ 직접 입력 · 🔄 모델 목록 새로 고침' 스위치).
  - 표시: **🆕** = 처음 받은 뒤 새로 나타난 모델(7일), **✍️** = 직접 입력한 모델, **⚠️** = yaml 에 있는데 그 회사 목록에서 사라진 모델 (같은 계열의 새 모델을 대신 쓰라고 알려 줌 — **자동으로 바꾸지 않음**).
  - 찾은 모델은 **고를 수 있게만** 됩니다. 직급의 기본(primary)·대안 모델은 절대 자동으로 바뀌지 않습니다.
  - FreeLLMAPI 는 등록한 무료 키에 따라 수백 개라(2026-11-02 실측 259개) 선택지에 바로 넣지 않고, '직접 입력'의 **찾은 모델에서 고르기**로 하나씩 넣습니다. `settings.yaml` 의 `model_catalog.selector_providers` 로 바꿀 수 있고, `auto_refresh: false` 면 자동으로 받지 않습니다 (🔄 버튼은 됨).
- **직접 입력** (사이드바 🧩 또는 🎛 상자 안 스위치)
  1. 제공처(openai·google·upstage·freellm·claude_cli·anthropic)를 고르고 **모델 이름을 API 에 보내는 이름 그대로** 넣습니다 (예: `gpt-6-luna`). 표시 이름은 선택.
  2. **🧪 연결 시험** — 아주 짧은 호출 1번 + 구조화 출력 1번으로 실제로 되는지 봅니다. 누르기 전에 예상 비용(가격을 모르면 '가격 미등록'), 누른 뒤 실제 토큰·비용·걸린 시간이 나옵니다. 꺼진 provider(비활성·키 없음·'🆓 무료 모델만')는 부르지 않습니다. 팀 업무에는 구조화 출력이 필요하므로 그것까지 ✅ 인지 보세요.
  3. **💾 추가** → 데이터 폴더의 `custom_models.json` 에 저장되고 바로 선택지에 ✍️ 로 나옵니다. `config/*.yaml` 은 바꾸지 않습니다. 지우면 그 모델을 고른 팀원은 기본으로 돌아갑니다.
- **강도(급)** — 상하 관계 규칙(부하는 상사보다 약한 모델)에 필요합니다.
  - 정하는 순서: `models.yaml` 의 `model_tiers` > 사람이 고른 급 > 이름으로 추정.
  - 이름 추정: 같은 계열(가능하면 같은 회사)의 비슷한 크기 모델을 기준으로, `nano`·`lite`·`haiku` 는 낮게, `mini`·`flash` 는 중간, `pro`·`opus`·`ultra` 는 높게, 버전 숫자가 높으면 위로(최대 두 줄) 옮깁니다. 새 줄을 만들지 않고 기존 줄에 '같은 급'으로 들어갑니다. 무료(freellm) 모델은 무료 줄 안에서만, 유료는 무료 줄 위에서만.
    예) `gpt-6-luna` → Opus 5.5 와 같은 급, `gpt-6-nano` → `gemini-3.5-flash` 급, `claude_cli:haiku` → `gemini-3.5-flash-lite` 급.
  - 추정이 틀리면 **📐 모델 강도(급)** 에서 '이 모델은 [gpt-5.5 와 같은 급 ▼]' 처럼 바꿉니다 (`custom_models.json` 에 저장).
- **가격**
  - 가격표(`pricing.yaml`·화면에서 고친 가격)에 없는 모델은 토큰은 기록하고 비용은 **'가격 미등록'** 으로 둡니다 (0 으로 치지 않음). 🏠 💰 사용량의 ⚙️ 가격표에 직접 입력한 유료 모델이 미리 줄로 나오므로 가격을 넣으면, 비어 있던 기록도 다시 계산됩니다.
  - 목록 API 가 가격을 알려 주는 경우(OpenRouter 형식 `pricing`)에만 그 값을 씁니다 (가격표에 없을 때). 2026-11-02 기준 OpenAI·Google·Anthropic·Upstage 목록 API 는 가격을 주지 않습니다 — 다른 사이트를 긁어 오지 않습니다.
- 무료 모델 규칙(무료 모델을 고른 팀원은 유료로 넘어가지 않음)·`disabled_providers`·쿨다운·`llm_concurrency` 는 새 모델에도 그대로 적용됩니다.

### 부서별 모델 고르기 (화면 — 🎛 부서별 모델 선택: 부서 → 👔 부장 → 팀 → 팀원)
특정 API 를 너무 많이 쓰지 않도록, 부서 단위로 모델을 고릅니다 (`dept_models_ui.py`).

- **여는 곳**: 🏠 메인 빌딩 아래 **🎛 부서별 모델 선택** (빌딩의 부서 띠를 누르면 그 부서로 펼쳐짐) · 🏢 팀 화면의 **🎛 부서별 모델 선택 — <부서>** (그 팀의 부서, 팀원 표는 지금 팀부터).
- **차례**: ① 👔 부장(⚖️ 비평가 · 🧭 부서장) 모델 → ② 부서의 팀마다 한 줄 (팀장 모델 · 이 팀을 비평할 모델과 출처 · ⚠️ 경고) → ③ 고른 팀 하나의 팀원 표.
  팀원 표는 고른 팀 하나만 그립니다 (화면을 다시 그릴 때 가볍게). 부장 모델은 위 '부서 부장 = 비평가' 절의 규칙을 따릅니다.
- 아래는 팀원 표의 규칙입니다 (예전 '🎛 팀원 모델 선택'과 같음, 저장 파일도 그대로).

### 모델 능력 · 사라진 모델 숨기기 (사진을 못 읽는 모델은 사진 일에서 빠짐)
모델마다 할 수 있는 일이 다릅니다. 텍스트 전용 모델에 사진을 보내면 실패하고, 제공처가 지운 모델은 고르는 순간부터 호출이 실패합니다.
그래서 앱이 **모델 능력**을 스스로 판단해, 그 일을 못 하는 모델과 사라진 모델을 **선택지에서 숨기고 실행 때 건너뜁니다** (`core/model_caps.py`, 능력표 `config/model_caps.yaml`).

- **능력**: 👁 사진 읽기(`vision`) · 📝 형식(구조화) 출력 · 스트리밍 · 📏 문맥(대략의 입력 토큰). 사진을 못 읽으면 선택지에 **🔤** 표시.
- **판단 순서** (뒤가 앞을 덮음): 이름 규칙(`gpt-oss-*`·`solar-*` → 텍스트 전용 등) → 능력표 `config/model_caps.yaml`(근거·실측 날짜 적음) →
  제공처 목록 API 메타데이터(Gemini `inputTokenLimit`, OpenRouter 형식 `input_modalities` 등) → **🧪 시험 결과** → **사람이 지정**.
  시험 결과·사람이 지정한 값은 데이터 폴더의 `model_caps.json` 에 저장합니다 (yaml 은 안 고침).
- **지금 설정의 텍스트 전용 모델 (사진 못 읽음)**: `freellm:gpt-oss-120b` · `freellm:gpt-oss-20b` (Groq) · `upstage:solar-pro2` · `upstage:solar-mini`
  (새 `solar-pro4` 도 2026-11-04 실측 — 사진을 보내면 400 'Image input is not allowed').
  무료 프록시의 Gemini(`freellm:gemini-*`)는 FreeLLMAPI 가 사진을 넘기는지 확인 전이라 **'모름'** → 사진 일에서는 숨깁니다 (🧪 사진 시험으로 확인하면 보임).
- **Claude 구독(`claude_cli`)도 사진을 읽습니다** — 메시지에 사진이 있으면 `claude -p --input-format stream-json` 으로 사진 블록을 보냅니다 (도구는 계속 끈 채로. 2026-11-04 실측).
- **일마다 필요한 능력** — 사진을 읽는 일(📐 도면 그림 가져오기, JD 이미지 등)은 👁 사진 읽기가 '된다'인 모델만, 팀 업무는 형식 출력이 '안 된다'로 확인된 모델을 뺍니다.
  - 실행 때: 메시지에 사진이 들어 있으면 자동으로 사진을 읽는 모델만 후보로 씁니다 → 대안으로 넘어가다 텍스트 전용 모델에 떨어지지 않습니다. 건너뛴 모델과 이유는 단계 기록('건너뛴 모델')에 남습니다.
  - 상하 관계 규칙·'🆓 무료 모델만 사용'·`disabled_providers` 는 그대로 먼저 적용됩니다.
- **사라진 모델** — 제공처 목록을 **최근(24시간 안)에 성공적으로** 받았는데 그 목록에 없으면 사라진 것으로 보고 숨기고 건너뜁니다.
  - 목록 받기가 실패했거나(오프라인·키 오류) 오래됐으면 **아무것도 숨기지 않습니다** (잘못 숨기지 않게). 목록 API 가 없는 Claude 구독, 사람이 직접 입력한 모델(✍️)도 숨기지 않습니다.
  - `models.yaml` 의 직급 기본·대안이 사라진 경우: 실행 때 건너뛰고 다음 후보를 쓰며, 화면에 한 번 ⚠️ 알림. yaml 은 자동으로 고치지 않습니다.
    **🧩 모델 목록** 의 **🔁 추천 대체 모델로 바꾸기** 를 누르면 데이터 폴더 `model_caps.json` 에 기록되고, 그 모델이 쓰이던 자리에 대체 모델(예: `solar-mini` → `solar-mini4`)을 씁니다 (**↩️ 대체 취소** 로 되돌림).
- **어디서 이유를 보나**
  - 🎛 팀원 모델 선택 아래 **ⓘ 숨긴 모델 N개 (이유)** — 누르면 숨긴 모델과 이유('제공처 목록에서 사라짐 (11-04 10:12 확인) (추천 대체: solar-mini4)' 등).
  - 🧩 모델 목록 · 직접 입력 맨 아래 **👁 모델 능력** — 사진 읽기에 쓸 수 있는 모델 목록과 **ⓘ 사진 읽기에서 숨긴 모델**, 모델마다 능력·근거,
    **🧪 사진 시험**(글자 하나가 든 약 1KB 그림을 보내 맞히는지 — 호출 1번, 사용량에 '사진 시험'), **사진 읽기 (사람이 지정)** 자동/된다/안 된다.
  - 직접 입력의 🧪 연결 시험에 **🖼 사진 읽기도 시험** 을 켜면 함께 확인합니다. 연결 시험의 구조화 출력 결과도 능력으로 기록됩니다.
- **이미 저장된 팀원 선택** 이 사라졌거나 그 일을 못 하는 모델이면: 저장값은 **지우지 않고**, 선택 상자 옆에 ⚠️ 와 이유를 보여 준 뒤
  이번 실행은 대체 모델(정했으면) 또는 기본(직급의 다음 후보)으로 진행합니다. 다른 모델을 고르면 그때 저장값이 바뀝니다.
- **다른 화면·기능에서 쓰기** (모델을 고르는 곳은 이 함수 하나로 거릅니다):
  ```python
  from core import model_caps
  shown, hidden = model_caps.selectable_models(model_caps.IMAGE_READING, keys)   # 선택지 (hidden = [Hidden(key, reasons)])
  models_ui.hidden_note(hidden, catalog)                                         # 'ⓘ 숨긴 모델 N개 (이유)'
  specs, notes = model_caps.runtime_specs(chain.candidates, model_caps.IMAGE_READING)  # 실행 후보
  llm_factory.available_candidates(chain, models, needs=model_caps.IMAGE_READING)     # 같은 것 (쓸 수 있는 provider 만)
  use, issues = model_caps.check_choices(saved_choices, model_caps.TEAM_WORK)          # 저장된 선택 점검
  ```
  필요한 능력은 `JobNeeds(vision=..., structured_output=..., min_context=..., label="일 이름")` 로 말합니다. 미리 정한 것: `TEAM_WORK`·`IMAGE_READING`·`ANY`(사라진 모델만 거름).

### 팀원별 모델 고르기 (화면 — 🎛 팀원 모델 선택)
특정 API 를 너무 많이 쓰지 않도록, 팀 화면의 조직도 아래 **🎛 팀원 모델 선택** 에서 에이전트마다 모델을 고를 수 있습니다.

- 선택지마다 **모델 · 제공처 · 비용**(구독 = Claude CLI / 유료 API / 무료 = FreeLLM)이 보이고, 오른쪽에 그 팀원의 **최근 7일 사용량**(호출 수·토큰·주로 쓴 모델)이 나옵니다.
- **기본** = 직급 설정 그대로 (아무도 고르지 않은 팀원 줄은 지금과 완전히 같음). **↩️ 모두 기본으로** 로 되돌립니다.
- **상하 관계 규칙** (강도는 `models.yaml` 의 `model_tiers`)
  - 팀원은 상사(팀장까지 이어지는 위쪽 모두)보다 강한 모델을 쓸 수 없습니다. 선택지에는 허용되는 모델만 나옵니다.
  - 상사의 모델을 **직접 고르면** 그 아래 팀원은 **더 낮은** 모델만 씁니다 (같은 강도도 안 됨). 예) 부장 = Claude Opus 5.5 → 그 부장 아래 차장·대리·사원은 Opus 보다 낮은 모델만.
  - '기본' 상사와는 **같은 강도까지** 허용합니다 — 팀장 기본값이 이미 가장 강한 Opus 5.5 라서, 이렇게 해야 부장도 Opus 를 고를 수 있습니다 (지금 직급 설정에도 대리의 대안 = 차장 기본 처럼 같은 강도가 있음).
  - 상사를 바꿔 규칙에 걸린 팀원은 **허용되는 가장 강한 모델로 자동으로 낮아지고**, 누가 바뀌었는지 알림이 뜹니다. 직접 고른 팀원은 저장값이 바뀌고, 기본 팀원은 저장 없이 그때만 낮아집니다(상사를 되돌리면 기본도 돌아옴).
  - 하위가 있는 팀원은 맨 아래 줄 모델을 고를 수 없습니다 (하위가 쓸 더 낮은 모델이 남도록).
- **실행 때**: 고른 모델이 첫 번째, 안 되면 직급의 대안 목록을 쓰되 상사 규칙을 넘는 대안은 뺍니다 (대안으로 넘어가도 규칙을 넘지 않음). `disabled_providers`·'🆓 무료 모델만 사용'·쿨다운·동시 호출 제한(claude_cli 1개)은 그대로 적용됩니다.
- **무료 모델을 고른 팀원**(직접 골랐거나 규칙으로 무료까지 낮아진 팀원)은 대안도 **무료 모델만** 씁니다. 무료 서버(FreeLLMAPI)가 꺼져 있으면 유료 API·구독으로 넘어가지 않고 '무료 서버 꺼짐 — Docker Desktop 실행 후 FreeLLMAPI 켜기'로 실패합니다 (사원 등 실무자는 '작성 실패'로 남고 나머지는 계속, 관리자면 업무가 오류로 멈춤). 기본 팀원은 예전처럼 직급 대안을 씁니다.
- 고른 모델을 지금 쓸 수 없으면 대안 모델을 슬쩍 보여 주지 않고 **⛔ 고른 모델 꺼짐** 으로 표시합니다 — 조직도 칸(`⛔ 모델 꺼짐 · 실패 예정` 또는 `→ 대안`), 에이전트 패널, 선택 상자 옆(이유 포함), 그리고 업무를 맡기기 전 경고. FreeLLMAPI 는 `restart: unless-stopped` 라 보통 Docker Desktop 만 켜면 다시 켜집니다 (안 되면 `docker compose -f C:/Users/<사용자>/freellmapi/docker-compose.yml up -d`).
- 바꾼 선택은 **다음에 맡기는 업무부터** 적용됩니다 (진행 중인 업무는 시작할 때의 모델 그대로).
- 저장 위치: 데이터 폴더의 `member_models.json`(팀원) · `department_models.json`(부장) (`AGENT_OFFICE_DATA_DIR` — 실행 폴더에서도 같은 파일을 봄). `config/*.yaml` 은 바꾸지 않습니다.
- 팀원별 사용량은 이 기능 이후의 호출부터 집계됩니다 (예전 기록에는 에이전트 정보가 없음). 브리프·검색 계획 같은 공용 호출은 팀원별 표에 넣지 않습니다.

1. `teams/_template` 폴더를 `teams/<새_팀_id>` 로 복사하고 `team.yaml`(조직도·검토 기준·하네스·업무 양식·자유 질문 범위 `scope`·예시 `free_examples`) 과 `skills/` 를 작성합니다.

   적지 않으면 맨 위 '📦 기타' 부서에 들어갑니다.
3. 새로 고치면 🏙 빌딩에 방이 생깁니다. 지금 층이 꽉 차면 위에 새 층이 생깁니다.

> 화면으로 만들기: 🛎 인포메이션 센터에 물었는데 맡을 부서가 없으면 새 부서·팀 초안을 만들어 줍니다 → 미리 보기에서 고치고 **✅ 확인하고 저장** (5장 '📮 접수 창구' 참고).

### 업무 양식 추가 (team.yaml `tasks`)
업무 하나 = 입력칸(`fields`) + 질문 템플릿 + 목표·완료 기준 + 하네스. 앱을 새로고침하면 **📋 업무 선택**에 나타납니다.

```yaml
tasks:
  - id: forecast
    title: 2) 주가 전망
    fields:                                  # type: text | textarea | number | date | select | checkbox | file
      - {key: stock, label: 종목 이름 또는 코드, required: true}
      - {key: horizon, label: 전망 기간, type: select, options: [1주, 1개월, 3개월]}
    question: "{stock} 종목의 향후 {horizon} 주가를 전망해줘."   # {key} = 입력값, 빈 값이 든 줄은 자동 삭제
    goal: "{stock} 종목의 {horizon} 시나리오별 전망 보고서"
    success_criteria: ["상승·기본·하락 시나리오와 확률을 제시한다"]
    instructions: |                          # (선택) 사고 절차·루브릭·퓨샷·JSON 형식 → 브리프 [배경]으로 모든 에이전트에게
      근거를 먼저 쓰고 점수는 마지막에 쓴다 …
    validators: [required_terms]             # 이 업무에서 추가로 돌릴 하네스
    harness_options: {required_terms: [시나리오, 확률]}   # 문자열 값의 {key} 도 입력값으로 바뀜
```
`start_date`·`end_date` 입력칸이 있으면 `{nights}`·`{days}` 가 자동으로 계산되어 템플릿에서 쓸 수 있습니다.
- `checkbox`: 켜면 `{key}` 가 '예', 끄면 빈 값(그 줄은 빠짐). `default: true` 로 켜 둘 수 있습니다.
- `file`: 파일 첨부 (`options` = 받을 확장자). '맡기기'를 누르면 `data/uploads/` 에 저장되고, 값은 저장 경로(데이터 툴이 읽음),
  `{key}_name` 은 원래 파일 이름(질문 템플릿용)입니다. 워크플로우 상태에는 파일 내용이 아니라 경로만 들어갑니다.
  `multiple: true` 면 여러 파일 — 값은 경로 목록, `{key}_name` 은 이름을 쉼표로 이은 글, `{key}_names` 는 이름 목록.
- 개인 문서를 다루는 팀은 team.yaml 에 `private: true` — 교훈·결정 요약을 `knowledge/`(공개 저장소)로 내보내지 않습니다 (8-1).

### 데이터 툴 추가 (team.yaml `tools`)
`core/tools/` 에 `run(question, inputs, models) -> ToolResult | None` 함수를 만들고 `core/tools/__init__.py` 의 `TOOLS` 에 등록합니다.
`inputs` 는 업무 양식의 입력값입니다. 결과는 모든 에이전트의 근거 자료와 화면 타임라인에 들어갑니다.
현재 툴: `stock_data`(주가·재무 지표·컨센서스·평가손익·추가 매수 한도), `travel_calendar`(여행 날짜·요일), `floorplan_input`(첨부 도면 → 레이아웃 JSON·면적표·검증, 방 최소 치수 기준표). 팀별 검색 요령·기간은 team.yaml `search`(`hint`, `news_timelimit` 등).

## 7-1. 주식 팀 — 판단을 돕는 장치

| 장치 | 내용 |
|---|---|
| 종목 식별 | 시장(KOSPI/KOSDAQ/NASDAQ…)·업종을 시세 툴이 먼저 확인 |
| 재무 지표 | EPS·ROE·영업이익률·성장률·부채비율·유동비율·배당성향·베타 (Yahoo 집계값 — DART 교차 확인 안내, 없으면 `확인 불가`) |
| 컨센서스 극단값 주의 | 평균 목표가가 현재가와 60% 이상 차이 나거나 최고/최저가 2배 이상이면 ⚠️ 표시 → 최신 리포트 확인 전에는 근거로 쓰지 않음 |
| 손절 참고가 | 단기 3~5% · 중기 8~10% · 장기 15% 이상 가격을 코드로 계산 |
| 보유 포지션 | 평가손익·본전 상승률, 현재/최대 비중으로 **추가 매수 가능 금액**, 25·50·100% 추가 시 **새 평균 단가** 시뮬레이션 |
| 근거 먼저 → 점수 | 추천·판단 업무는 리스크 → 기회 → 점수 순서 강제 + 1점/5점(추천), 4.35 매수/1.55 매도(판단) 기준점 예시 |
| 출처 규칙 | 모든 수치 `[출처, YYYY-MM-DD]`, 우선순위 DART → KRX → 네이버 금융·FnGuide → 증권사 리포트 → 뉴스, 블로그·카페·종목토론방은 검색 결과에서 제외 (team.yaml `search.exclude_domains`) |
| 🧮 코드 검산 | 최종 결과 아래에 LLM 이 아닌 코드가 다시 계산한 점수표·평균 매수가·손익비·평단을 따로 표시 (채택 시 저장 파일에도 포함) |

판단 업무 결정 밴드: 종합 = Σ(점수×가중치)÷100 → **3.75 이상 매수 / 2.50~3.74 보유 / 2.50 미만 매도**, `데이터 부족` 3개 이상이면 **판단 보류**.

## 7-2. 📚 개념 편집 팀 (IT 개념 카탈로그)

사이드바 **팀 선택 → 개념 편집 팀** — 다른 팀과 똑같이 조직도·에이전트 패널(칸을 누르면 그 에이전트의 진행 상황)·이미지 편집·타임라인을 쓰면서, GitHub [jeong-yun/CS](https://github.com/jeong-yun/CS/tree/main/Term/Every_day) 의 IT 개념 카탈로그에 항목을 작성(추가·수정)·삭제합니다. 사이드바 **📁 개념 카탈로그** 에서 폴더 위치와 git 상태를 확인합니다.

1. CS 저장소를 clone: `git clone https://github.com/jeong-yun/CS.git` (기본 위치: 프로젝트 폴더 옆, `config/settings.yaml` 의 `concept.catalog_dir`)
2. **✍️ 작성**에 개념명·초안 입력 → 추가/수정은 **자동 판정**: 같은 개념이 독립 항목으로 있거나 다른 항목의 `7. 변형·확장 상세` 소절에 들어 있으면 **수정**(그 항목/부모 항목), 없으면 **추가** (판정은 화면에서 바꿀 수 있음). **관련 기존 항목**도 코드가 찾아 함께 보냄
3. **개념 편집 팀**(편집장 → 수석에디터 → 팩트체크·계보분석)이 'IT 개념 프롬프트'(`teams/concept/skills/it_concept_prompt.md`) 규칙으로
   1단계 비교(이중 해리) → 2단계 검증 로그 → 카탈로그 형식 최종본 → GitHub 요약 → 적용 계획(JSON) 을 작성

     - 편집장 검토는 1만 자 최종본을 통째로 다시 쓰지 않고 **고칠 곳만** `찾을 문장 → 바꿀 문장`으로(`review_mode: edit`). 찾을 문장이 최종본에 정확히 한 번 있을 때만 바꾸고, 못 찾은 것은 '검증 기록'에 남김. 고칠 곳이 너무 많으면 모델이 전문을 다시 쓸 수도 있음

     - 실측(2026-10-27, 같은 요청·같은 팀원 모델): 17.4분 → 9.9분, API 비용 $0.26 → $0.10, 구독 Opus 출력 6.5만 → 2.9만 토큰. 가장 긴 대기는 계보분석 초안 모델(gemini-3.8-flash 약 5분) — '🎛 부서별 모델 선택'에서 더 빠른 모델을 고르면 더 줄어듦

5. 채택 후 결과 영역의 **📚 카탈로그 반영** → **💾 커밋** → **🚀 GitHub 에 푸시** (버튼을 눌러야만 올라감)
   - GitHub 웹에서 직접 고친 커밋이 있어도 푸시가 거절되지 않음: 푸시 전에 `git fetch` → GitHub 에만 있는 커밋이 있으면 **자동으로 `git pull --rebase`**(내 커밋을 그 위로 다시 쌓기) → 카탈로그를 다시 읽어 깨지지 않았는지 확인 → 푸시. 몇 개를 합쳤는지 화면에 표시
   - 양쪽에서 **같은 부분**을 고쳐 충돌하면 `git rebase --abort` 로 합치기 전 그대로 되돌리고(작업 폴더 깨끗, 내 커밋 유지) **푸시하지 않음** — 충돌한 파일과 해결 방법(터미널에서 `git pull --rebase` → 직접 고치기 → `git rebase --continue`)을 안내
   - 커밋 안 된 변경이 남아 있으면 rebase 를 시작하지 않고 먼저 커밋하라고 안내

## 7-3. 여행 경로 지도 (국내·해외 여행팀)

## 7-4. 🎵 음악 팀 (Gemini Lyria — 노래·반주 만들기와 편집)

주제·길이·장르를 넣으면 팀이 가사와 Lyria 프롬프트를 쓰고, 끝나면 **Google Gemini Lyria** 로 MP3 를 만듭니다.
만든 곡은 화면에서 듣고·받고·편집(자르기·템포·키·페이드·리버브·음량)할 수 있고, 채택하면 `.md` 옆에 `.mp3` 도 저장합니다.

| 단계 | 내용 |
|---|---|
| 조직도 | 팀장·음악PD(브리프: 용도·길이·분위기·보컬 여부·언어) → 부장·검수 → 대리·작사가(섹션 태그 가사) / 차장·작곡편곡(Lyria 스타일 프롬프트) |

| 결과 형식 | 최종 답변에 ```` ```lyrics ```` (가사, `[Verse]`·`[Chorus]` 태그) 와 ```` ```lyria ```` (영어 스타일 프롬프트, `[0:00 - 0:15]` 시간표) 블록 |
| 하네스 `music_prompt` | 블록이 있는지, 반주는 `Instrumental only, no vocals.` 가 있고 가사가 없는지, 노래는 섹션 태그·곡 길이에 맞는 줄 수·음절 수, 실존 아티스트 이름·'in the style of' 표현, 시간표 구간이 길이 안에서 겹치지 않고 끝까지 가는지 → 틀리면 재작성 |

| 길이 확인·채점 | mutagen 으로 실제 길이를 재고, Gemini 가 곡을 **듣고** 브리프와 비교해 1~5점 채점 → 점수를 화면에 표시 (`max_regenerations` 를 1 이상으로 두면 기준 미만일 때 자동으로 다시 생성 — 기본 0, 다시 만들 때마다 과금) |
| 편집 (CPU) | 편집 요청 → 보조 모델이 정해진 연산(`trim`·`loop`·`fade`·`concat`·`tempo`·`pitch_shift`·`gain`·`eq`·`reverb`·`compress`·`normalize`)만으로 편집 계획(JSON) → 코드가 값 범위 검사 → 실행 → 결과 파일의 길이·라우드니스(LUFS)를 다시 재서 계획과 비교 (`core/audio_edit.py`) |

설정은 `config/settings.yaml` 의 `music:` — 자동 생성 여부(`auto_generate`, **기본 false: '🎵 곡 만들기' 버튼을 눌렀을 때만 생성**), 모델·가격(`cost_usd`), 채점(`grade`, `grade_model`, `grade_threshold`),
자동 재생성 횟수(`max_regenerations`, 0 이면 안 함), 템포·키 고품질 모드(`edit_high_quality`, 3분 곡 약 30초 → 90초).

**한계 (꼭 알아 두기)**

- **유료**: 생성 1회마다 비용이 듭니다 (클립 약 $0.04, 곡 약 $0.08 — 화면의 '예상 비용'은 대략값, 실제 요금은 Google 가격표 기준). 자동 재생성·🔁 다시 만들기도 매번 과금됩니다. `GOOGLE_API_KEY` 필요.
- **매번 결과가 다름**: 같은 프롬프트라도 곡이 달라집니다 (재현 불가). 마음에 드는 곡은 바로 채택·저장하세요.
- **수정 불가(single-turn)**: Lyria 는 만들기만 하고 고칠 수 없습니다. 편집은 모두 **후처리**(자르기·템포·키·EQ·리버브·음량)이며 가사·멜로디·악기 구성은 바꿀 수 없습니다 → 다시 생성하거나, 부분 편집이 되는 GPU 생성 모델(예: ACE-Step 1.5)이 필요한데 이 PC(내장 그래픽, NVIDIA GPU 없음)에서는 쓸 수 없습니다.
- **MIDI·스템 없음**: Lyria 는 섞인 MP3 한 개만 줍니다 (MIDI·악기별 트랙 없음).
- **SynthID 워터마크**: 생성 음원에는 들리지 않는 AI 생성 표식이 들어 있습니다.
- **거부되는 요청**: 실존 가수 목소리·기존 곡 가사는 안전 필터로 거부됩니다 (하네스가 미리 걸러 냄).
- 템포·키 변경은 원음 대비 약간의 음질 변화(Rubber Band 시간 늘이기)가 있습니다.

**편집 도구 선택 이유** — `pydub`·`pyrubberband` 는 ffmpeg·rubberband 실행 파일이 필요한데 이 PC 에 없어서,
같은 일을 내장 라이브러리로 하는 **pedalboard**(MP3 읽기/쓰기 LAME, 템포·키 Rubber Band, EQ·리버브·컴프레서)와
**pyloudnorm**(LUFS), **mutagen**(MP3 길이), **scipy**(피크 리미터)를 씁니다. ffmpeg 설치 없이 `pip install -r requirements.txt` 만으로 동작합니다.

**나중 단계 — 보컬 크게/반주만 (스템 분리, Demucs)**: Demucs 는 torch·torchaudio(수 GB) 와 저장용 ffmpeg 가 필요해 이 환경에서는 깔끔하게 설치되지 않아
넣지 않았습니다. 지금 '보컬 크게', '반주만' 같은 요청은 화면에서 이유를 안내합니다. 넣을 때는 `pip install demucs` + ffmpeg 설치 후

**배치 엔진** (`core/floorplan_solver.py`, CPU 전용 — `pip install ortools`)

예전 자동 분할(앞 띠 / 복도 / 뒤 띠, 방 너비 = 면적 비례)은 큰 집에서 '28m 일자 복도 + 1.4×6m 욕실 + 2.5×6m 침실' 같은 막대 평면을 만들었습니다.
지금은 방마다 직사각형 변수(x·y·폭·깊이)를 두고 제약 충족 문제로 풉니다.

| 단계 | 내용 |
|---|---|
| 외곽 유형 | `rect` 일자형 · `L` ㄱ자형 · `U` ㄷ자형 · `courtyard` 중정형. **기본은 꽉 찬 일자형**(외곽 효율 100%) — ㄱ·ㄷ·중정형은 이유가 있을 때만: 마당·데크 요청 → ㄱ자(안쪽 모서리 = 마당), 중정 요청 → 중정형(안 되면 ㄱ자 안쪽 마당), `placement: wing` → ㄱ자, LLM 이 `typology` 를 직접 씀. 바닥 넓이는 LLM 외곽 넓이와 같게 유지 |
| 특수실 | 큰 수영장·차고(20㎡ 이상)는 **일자형 동쪽 끝 블록**(깊이 전체, 벽으로 분리)에. `"placement": "wing"` 이면 ㄱ자 날개(안쪽 모서리는 데크), `"placement": "annex"` 면 **별채**로 빼고 메모(본채 도면에는 그리지 않음) |
| 바깥 공간 | 마당·데크·테라스(`kind: yard/deck`, 이름으로도 알아봄)는 실내 바닥에서 빼서 `layout.outdoor` 에 — ㄱ·ㄷ자 안쪽 모서리(빈 곳 넓이 = 요청 넓이, 없으면 바닥의 15%·25~60㎡, 폭·깊이 ≥ 4.2m) 또는 건물 앞. 꺾인 외곽의 빈 곳은 항상 데크·마당으로 지정돼 '요청하지 않은 빈 마당'이 남지 않음 |
| 모형 | 외곽을 직사각형 블록으로 쪼개고 블록마다 높이가 정해지지 않은 '줄' 2~4개 → 방은 이어진 줄 몇 개에 걸치고, 줄마다 방 길이 합 = 블록 길이 (빈틈없이 채움이 구조로 보장됨). 방이 많으면 0.6m 격자로 먼저 풀어 0.3m 풀이의 출발점으로 씀 |
| 하드 제약 | 겹침 없음 · 최소 폭·면적 · 목표 면적 ±18% · 장단변비(욕실 1:2, 침실 1:1.6 …) · 꼭 이웃할 방은 1.2m 이상 벽 공유(문) · 트인 방(LDK)은 2.4m 이상 · 거실·침실은 외벽(또는 중정) · 현관은 외벽 · 모든 방이 현관(위층은 계단)에서 문으로 이어짐 · 안방 묶음은 안방을 거쳐 |
| 목표 | 목표 면적 오차 + 복도 면적 최소 + 둘째 복도 조각 벌점 + 이웃하면 좋은 방 + 네모난 방 + 현관에서 짧은 동선 + 현관은 앞(도로) 쪽 + 남향 거실 + 물 쓰는 곳 모으기 + 구역 모으기(침실은 안방 가까이, 식당·주방은 거실 가까이) |
| 복도 한 줄기 | 복도는 많아야 2조각(한 줄기 + 앞 복도나 현관에서 갈라지는 가지 하나), 복도끼리는 끝과 끝·T자로만 만남(긴 변을 맞댄 나란한 조각은 하드 제약으로 금지). 남는 면적은 거실·침실이 나눠 갖고(욕실·현관 같은 작은 방은 +5%까지만) 틈은 수납으로 메움. 일렬로 이어진 조각은 풀이 뒤 한 방으로 합침(`merge_corridors`) — 예전 '현관 옆 짧은 복도 여러 개 나란히' 해결 |
| 시간·실패 | 층 하나에 3~10초(방 수에 따라). 답이 없으면 제약을 조금 풀어 다시, 그래도 없으면 예전 단순 분할 + "배치 엔진(CP-SAT)이 답을 찾지 못해 …" 메모. 같은 입력은 캐시로 한 번만 풂 |
| CPU 가 바쁠 때 | 아래 'CPU 부하와 풀이 시간' 참고 — 작업량이 모자라면 최선 답에서 이어서 풂 (벽시계 최대 2.5배) |

**후보안 A/B/C** — 좌표 없는 프로그램이면 서로 다르되 모두 '말이 되는' 안을 최대 3개 만들어 **📐 도면** 상자의 탭으로 비교합니다:
큰 수영장·차고가 있으면 *일자형 + 끝 블록* / *수영장 별채* / *ㄱ자 날개 + 데크*, 마당·중정을 요청했으면 *중정형* ↔ *ㄱ자 안쪽 마당* ↔ *일자형 + 앞마당*, 그 밖에는 *일자형 비율 바꾸기*(길쭉한 남향 2.2 / 깊고 짧은 1.25) → 현관 방향 바꾸기.
요청하지 않은 빈 마당이 생기는 ㄱ·ㄷ·중정형은 후보로도 만들지 않습니다. B·C 는 검증을 통과한 안을 먼저 고릅니다.
A 는 하네스가 검증한 기본 배치, 처음에는 검증을 통과한 안 중 점수(오류·경고·복도 몫·장단변비·이웃·외곽 효율·복도 조각 수)가 가장 높은 안을 채택하고, **후보안 X 채택** 버튼으로 바꾸면 내려받기·저장 파일이 그 안으로 다시 만들어집니다.

**CPU 부하와 풀이 시간** — CP-SAT 는 시간 제한(벽시계)에서 멈추므로, 다른 무거운 실험이 CPU 를 쓰면 같은 시간에 찾는 양이 줄어 평면이 나빠집니다
(특히 0.3m 다듬기가 답을 못 찾아 0.6m 배치로 물러남). 그래서 `solve_model()` 이 풀이마다 **작업량(CP-SAT 결정적 시간)** 을 재서,
한가할 때의 작업량(`DET_PER_SEC` × 시간 제한)에 못 미치고 최적도 아니면 지금까지의 최선 답을 출발점(hint)으로 **이어서** 풉니다 (벽시계는 시간 제한 × `WALL_CAP` 2.5 까지, 답이 아직 없으면 작업량과 상관없이 한도까지).
`FLOORPLAN_STOP=wall` 환경 변수로 예전 방식(한 번만)으로 돌릴 수 있습니다.

측정 (i5-1135G7 4코어/8스레드 노트북, BIG 샘플 = 100평·방 15개, 0.6m→0.3m 두 단계 각 5초, 바쁜 PC = `while True` 프로세스 8개)

| 방식 | 한가한 PC | 바쁜 PC |
|---|---|---|
| 벽시계 10초 (예전) | 11초, 검증 통과 5/5 | 11초, 통과 5/7 — 7번 중 3번 0.3m 다듬기 실패(0.6m 배치로 대신) |
| 벽시계 10초, 워커 4개 | – | 11초, 통과 1/3 (워커를 줄이면 더 나쁨) |
| `max_deterministic_time` + 벽시계 3배 | **31초** (병렬 풀이에서 결정적 시간 한도가 지켜지지 않아 늘 벽시계 한도까지) | 31초, 통과 3/3 |
| **작업량 재고 이어 풀기 (지금)** | 11초 (대개 첫 풀이로 끝남) | 16~24초, 통과 4/4, 0.6m 대체 없음 |

- 한가할 때 벽시계 1초에 쌓이는 결정적 시간은 0.22~0.66(중앙 약 0.5), 바쁠 때 0.15~0.4 — 한가할 때는 대개 첫 풀이로 끝나도록 `DET_PER_SEC = 0.3` (0.4 로 두니 한가할 때도 자주 이어 풀어 후보안 3개가 19초 → 37초로 늘었다).
- 트레이드오프: 바쁜 PC 에서는 후보안 3개(층 하나씩)가 최대 2.5배(예: 30초 → 50~75초) 걸릴 수 있습니다. 한가한 PC 는 그대로입니다.
- 이전 세션에서 시도한 `interleave_search` + 결정적 시간(결과가 완전히 같아짐)은 검사 한 번에 약 40초라 쓰지 않습니다.
- 측정 스크립트는 저장소에 넣지 않았습니다 (결과만 이 표에).

## 8-1. 피드백(교훈·결정 요약)을 GitHub 에 올리기 — `knowledge/`

`data/` 는 `.gitignore` 라 GitHub 에 올라가지 않습니다. 그중 **다음 업무를 더 잘하게 만드는 학습**만 텍스트로 꺼내 `knowledge/` 에 둡니다 (`core/feedback_sync.py`).
저장소가 **공개**이므로 개인 정보가 들어갈 수 있는 원문은 올리지 않습니다.

| 파일 | 내용 |
|---|---|
| `knowledge/lessons.jsonl` | 에이전트별 교훈 (팀·에이전트·👍/🔧·문장·켜짐 여부·작성 시각) |
| `knowledge/decisions.jsonl` | 결정 요약 (팀·문의 대상·채택/반려·채택한 에이전트·직접 수정 여부·만족도·코멘트 유무·시각) |
| `knowledge/교훈.md` | GitHub 에서 읽기 좋게 팀 → 에이전트별로 묶은 교훈 + 팀별 결정 수·평균 만족도 |

- **올리지 않는 것**: 질문·최종 답변·코멘트 원문(보유 종목·매수가·여행 일정 등), 교훈 끝에 붙는 `(사람 코멘트: …)`, 사용량·API 키 정보, `results/` 결과 파일,
  team.yaml 에 `private: true` 인 팀(👔 포트폴리오·자소서 팀)의 교훈·결정 요약 전부 — 교훈 문장에도 경력 내용이 들어갈 수 있어서. 가져오기(import)에서도 빠집니다.
- **자동**: 실행용 `Agent_Office_실행.bat` 이 `AGENT_OFFICE_KNOWLEDGE_DIR` 를 `Project\LLM\Agent_office\knowledge` 로 지정 → 채택·반려·교훈 수정 때마다 파일을 다시 씁니다(내용이 같으면 그대로).
  그다음 평소처럼 `git add` → `git commit` → `git push` 하면 피드백도 올라갑니다. 테스트·개발용 실행은 이 변수가 없어 파일을 건드리지 않습니다.
- **새 PC**: `git clone` 후 앱을 켜면(변수 지정 시) `knowledge/lessons.jsonl` 의 교훈 중 DB 에 없는 것을 가져옵니다 → 에이전트가 같은 교훈으로 일합니다. 같은 교훈은 두 번 넣지 않습니다.
- **수동**: `python scripts/sync_feedback.py` (내보내기) · `python scripts/sync_feedback.py import` (가져온 뒤 내보내기)

### 성능 (화면 전환 속도)

Streamlit 은 클릭할 때마다 `app.py` 전체를 다시 실행하므로, 그때마다 하는 일을 줄여 두었습니다.

- **설정 YAML·SQLite 조회·아바타 폴더**: 파일의 (수정 시각, 크기)가 그대로면 직전에 읽은 결과를 씁니다 (`core/memo.py`). 파일을 고치거나 DB 에 기록이 생기면 바로 다시 읽고, 방금(2초 안) 바뀐 파일은 캐시하지 않습니다 — 그래서 업무가 진행 중일 때는 DB 를 매번 새로 읽습니다.
- **개념 팀 사이드바**: git 정보(원격·브랜치·안 올린 커밋·마지막 커밋·status)와 카탈로그 파싱을 캐시합니다. 카탈로그 파일·`.git` 의 HEAD·index 등이 바뀌거나 30초가 지나면 다시 읽고, 커밋·푸시·pull 버튼을 누르면 바로 새로 읽습니다.
- **무거운 모듈**: 도면·3D(matplotlib·ezdxf·trimesh·scipy)는 실제로 도면을 그릴 때 불러옵니다 → 앱 시작이 빨라집니다.

측정 (서버 쪽 스크립트 시간, 같은 PC·같은 데이터 복사본):

```bash
python scripts/bench_ui.py --data data --catalog ../../../CS/Term/Every_day   # 화면별·전환 시간
python scripts/bench_ui.py --data data --profile stock                         # 한 화면 cProfile 상위 함수
```

`data/` 는 임시 폴더에 복사해서 쓰므로 원본은 바뀌지 않습니다. 브라우저가 화면을 그리는 시간은 빠져 있습니다.

## 11. Git — 수정한 내용 올리기

코드는 GitHub `jeong-yun/Project` 저장소(`main` 브랜치)의 `LLM/Agent_office` 폴더에서 관리합니다.

```powershell
cd Project            # 저장소 최상위 폴더
git pull              # 다른 PC 에서 올린 내용 먼저 받기
git status            # 바뀐 파일 확인 — .env, data/, results/ 가 없어야 정상 (.gitignore 로 제외)
git add LLM/Agent_office
git commit -m "무엇을 왜 바꿨는지 한 줄"
git push
```

- 처음 쓰는 PC 에서는 커밋 작성자를 한 번 설정합니다 (이 저장소에만 적용): `git config user.name "이름"`, `git config user.email "메일"`
- 처음 push 할 때 브라우저 GitHub 로그인 창이 뜹니다 (Git Credential Manager).
- 저장소 만들기·폴더 이름 바꾸기·실수로 `.env` 를 올렸을 때 대처 등 자세한 내용은 [GIT_GUIDE.md](GIT_GUIDE.md).

## 12. 트러블슈팅

| 증상 | 해결 |
|---|---|
| 조직도 칸에 `모델 없음` | `.env` 에 해당 직급의 primary 또는 fallback provider 키를 입력 후 앱 재시작 |
| `ModuleNotFoundError` | 가상환경이 활성화됐는지 확인 후 `pip install -r requirements.txt` |
| `streamlit` 명령을 찾을 수 없음 | `python -m streamlit run app.py` 로 실행 |
| 포트 8501 사용 중 | `--server.port` 옵션으로 다른 포트 지정 |
| PowerShell 에서 Activate.ps1 실행 차단 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 후 재시도 |
| 검증 기록에 `credit balance is too low` | Anthropic 크레딧 충전 (그 전까지는 대안 모델이 답변) |
| 검증 기록에 `404 ... no longer available` | 모델 단종 — 에러 메시지가 안내하는 새 모델명으로 `config/models.yaml` 수정 |
| 검증 기록에 `429 ... quota` | 무료 등급 할당량 초과 — 결제 등록 또는 다른 모델로 변경 |
| `503 ... high demand` (요청 폭주) | 해당 모델 서버가 일시적으로 붐빔 — 앱이 자동으로 2초·5초 뒤 같은 모델로 다시 시도하고, 그래도 안 되면 대안 모델로 처음부터 다시 씁니다. 실무자 한 명이 끝내 실패해도 "⚠️ 작성 실패" 로 표시하고 팀은 계속 진행합니다 |
| 웹 검색 자료 0건 | 네트워크 확인. 검색 실패해도 답변은 계속 진행됩니다 (자료 없이) |
| 업데이트 후 화면에 AttributeError | 코드가 바뀌는 중에 실행한 경우 — 앱을 재시작하세요 |
