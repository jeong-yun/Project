# AI 거버넌스 팩 — LLM 기반 보안 학습데이터 생성 파이프라인

이 폴더는 [Snort 룰 기반 IPS/WAF 학습데이터 생성 파이프라인](../../README.md) 을 **NIST AI RMF**, **ISO/IEC 42001**, **한국 AI 기본법** 형식으로 정리한 거버넌스 문서다.
LLM 이 공격·정상 HTTP 요청 샘플을 만들고(생성), 다른 LLM 이 판정하고(검토: pass/fix/drop), 코드가 룰 조건으로 다시 확인하고, 사람이 결과를 고르고 확정하는 구조다.

- 대상: 이 공개 저장소의 코드와 문서만. 회사 데이터·기존 학습 로그·내부 환경 정보는 넣지 않았다.
- 수치: 저장소 문서에 이미 있는 것만, 출처 파일과 줄을 함께 적었다.
- 법·표준: 출처 주소를 적었다. 확실하지 않은 것은 "확인 필요". 법 해석은 권위 있는 해석이 아니다.
- 작성: 2026-10-29, 저장소 `main` 기준.

## 한눈에 보기

**잘 된 것**
- 라벨을 LLM 이 아니라 **룰 조건과 코드 검사**로 정한다. LLM 이 틀리거나 조작돼도 룰 조건을 통과하지 못하면 남지 않는다.
- 하루치 학습 로그 190,226줄 전체 검증에서 불일치 110줄(0.06%)을 찾아 원인(로그 표기)을 고친 뒤 0 ([요약 65행](../보고용/진행_설계_요약.md)).
- 검토 모델의 **안전 거부 편향**을 발견해 측정하고 대응: 거절·안전 사유 룰만 대체 모델로 다시 검토, 요청 389개에서 공격 씨앗 1,442 → 8,724, 공격 샘플 없는 룰 903 → 185 ([요약 163행](../보고용/진행_설계_요약.md)).
- 요청 100개(룰 300개) 처리 약 7시간 → 약 28분 (동시 요청 자동 조절, 속도 제한 0건) ([요약 72행](../보고용/진행_설계_요약.md)).
- 요청마다 모델·토큰·결과 수·빠진 이유가 `meta.json`·`.rejected.jsonl` 에, 사람의 수정·확정이 `edits.json`·`manifest.json`(sha256) 에 남는다.

**가장 큰 잔여 위험**
1. **R05 (높음)** 기존 학습 로그의 payload 원문이 생성·검토 요청에 예시로 붙어 외부 LLM 으로 나간다. 마스킹 단계가 없다.
2. **R01 (중간)** 안전 거부 편향은 줄었지만 공격 샘플 없는 룰 185개가 남았고, 유형별 삭제율 경보가 없다.
3. **R02 (중간)** 코드 검사는 근사다. 실제 Snort 로 탐지되는지 확인하는 단계가 없다.
4. **R11 (중간)** 검토 모델이 문서마다 다르게 적혀 있고, `meta.json` 에 지시문 지문·추론 강도가 없다.
5. **R04 (중간)** 금액 기준 비용 상한이 없다 (요청 수 기본값 1, 확인 창은 있음).
