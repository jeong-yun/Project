# AI 거버넌스 팩 — LLM 기반 보안 학습데이터 생성 파이프라인

이 폴더는 [Snort 룰 기반 IPS/WAF 학습데이터 생성 파이프라인](../../README.md) 을 **NIST AI RMF**, **ISO/IEC 42001**, **한국 AI 기본법** 형식으로 정리한 거버넌스 문서다.
LLM 이 공격·정상 HTTP 요청 샘플을 만들고(생성), 다른 LLM 이 판정하고(검토: pass/fix/drop), 코드가 룰 조건으로 다시 확인하고, 사람이 결과를 고르고 확정하는 구조다.

- 대상: 이 저장소의 코드와 문서. 데이터·실행 결과·환경 정보는 넣지 않았다.
- 수치: 저장소 문서에 이미 있는 것, 또는 2026-10-29 에 개수만 다시 센 것. 출처 문서와 절(또는 함수)을 함께 적었다. 줄 번호는 코드가 바뀌면 틀어지므로 쓰지 않는다.
- 법·표준: 출처 주소를 적었다. 확실하지 않은 것은 "확인 필요". 법 해석은 권위 있는 해석이 아니다.
- 작성: 2026-10-29. 같은 날 위험 등록부의 계획 통제 3개(R05 참고 예시 마스킹, R11 생성 이력, R01 거부 편향 경보)를 코드에 넣고 잔여 위험을 고쳤다.

## 한눈에 보기

**잘 된 것**
- 라벨을 LLM 이 아니라 **룰 조건과 코드 검사**로 정한다. LLM 이 틀리거나 조작돼도 룰 조건을 통과하지 못하면 남지 않는다.
- 하루치 학습 로그 190,226줄 전체 검증에서 불일치 110줄(0.06%)을 찾아 원인(로그 표기)을 고친 뒤 0 ([요약 5장](../보고용/진행_설계_요약.md)).
- 검토 모델의 **안전 거부 편향**을 발견해 측정하고 대응: 거절·안전 사유 룰만 대체 모델로 다시 검토, 요청 389개에서 공격 씨앗 1,442 → 8,724, 공격 샘플 없는 룰 903 → 185 ([요약 12장](../보고용/진행_설계_요약.md)).
- 요청 100개(룰 300개) 처리 약 7시간 → 약 28분 (동시 요청 자동 조절, 속도 제한 0건) ([요약 6장](../보고용/진행_설계_요약.md)).
- 요청마다 모델·토큰·결과 수·빠진 이유가 `meta.json`·`.rejected.jsonl` 에, 사람의 수정·확정이 `edits.json`·`manifest.json`(sha256) 에 남는다.
- **2026-10-29 적용한 통제 3개** (시험 19개, 합성 payload 만: `python -m unittest discover -s tests -v`)
  - **R05 참고 예시 마스킹** (기본 켬, [7장](07_마스킹_제안.md)): 외부 LLM 에 보내기 전 Host·쿠키 값·인증값·IP·이메일·JWT·비밀 이름 파라미터·긴 무작위 값을 문서용 값으로. 오류나 룰 조건이 깨진 예시는 보내지 않음. 로컬 예시 후보 전체에 돌려 보니 후보의 99% 에서 바꿀 값이 나왔고, 마스킹 오류 0, 룰 조건이 깨져 뺀 예시 약 3%.
  - **R11 생성 이력**: 3.2·3.3 `meta.json` 의 `provenance` 에 실제로 쓴 생성·검토·대체 모델, temperature·max_tokens·추론 강도, 지시문 sha256. 문서의 검토 모델 표기를 설정 파일과 맞춤.
  - **R01 거부 편향 경보**: 3.5 가 공격 유형별 거부 비율을 세어 기준(5%)을 넘으면 경고. 다시 만들기 전의 검토 결과에 돌려 보니 거부가 심했던 두 실행에서 각각 10개·16개 유형을 잡았고, 정상 실행에서는 경고 0.

**남은 위험과 계획**
1. **R02** 코드 검사는 근사다. 실제 Snort 로 탐지되는지 확인하는 단계가 없다.
2. **R04** 금액 기준 비용 상한이 없다 (요청 수 기본값 1, 확인 창은 있음).
3. **R05** 마스킹은 패턴 기반이라 이름이 평범한 파라미터에 든 개인정보는 못 잡는다. 사용자 룰을 넣으면 그 룰 원문도 LLM 에 간다. 제공자별 데이터 보관·학습 사용 조건은 아직 기록하지 않았다.
4. **R01** 경보는 알리기만 한다. 다시 만들기는 사람이 누른다.
5. **R08** 모델 교체 때 쓰는 고정 회귀 세트가 없다.
