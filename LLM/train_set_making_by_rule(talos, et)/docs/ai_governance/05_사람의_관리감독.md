# 5. 사람의 관리·감독 지점과 증적

> 이 파이프라인에서 사람은 **샘플 하나하나를 승인하지 않는다**. 실행을 시작·멈추고, 모델을 고르고, 빠진 샘플을 다시 만들지 정하고, 검증 결과를 보고 고치거나 지우고, 마지막에 버전을 확정한다.
> 과학기술정보통신부 「고영향 인공지능 사업자 책무 가이드라인」은 사람의 관리·감독을 Human-in-the-loop(AI 가 사람의 결정을 보조) / Human-over-the-loop(AI 가 결정, 사람이 결과를 보고 개입 가능) / Human-out-of-the-loop(AI 가 독자 결정) 로 나눈다고 한 법무법인 해설이 전한다 (법무법인 지평 칼럼, 2026-07-24: https://www.jipyong.com/kr/board/news_view.php?seq=15374 — 가이드라인 원문 확인 필요).
> 이 분류로 보면 생성·검토는 **Human-over-the-loop** (LLM 이 샘플을 만들고 판정하고, 사람은 결과를 보고 개입), 버전 확정은 **Human-in-the-loop** (기준 모델 등급은 참고, 최종 결정은 사람) 에 가깝다.

## 5.2 자동으로 남는 증적 (요청 단위)

| 파일 | 만드는 곳 | 주요 필드 |
| --- | --- | --- |
| `_2_generated/<요청>.meta.json` | `3_2_generate.generate` | `generator`, `finished_at`, `seconds`, `rules_missing`, `cut_responses`, `regex_examples`, `local_check`(ok·fail·unknown), `usage` |
| `_2_generated/raw/<요청>.try<n>.txt` | 같음 | 생성 모델 응답 원문 (시도마다) |
| `_3_reviewed/<요청>.meta.json` | `3_3_review.review` | `reviewer`, `rules_kept`, `samples`, `fixed`, `rejected`, `usage.reviewer_primary`/`reviewer_fallback`, `fallback`, `refused`, `redo` |
| `_3_reviewed/raw/<요청>.try<n>.txt`, `.fb.try<n>.txt` | `3_3_review.ask` | 검토·대체 검토 응답 원문 |
| `_3_reviewed/<요청>.rejected.jsonl` | `3_3_review.review` | 빠진 샘플마다 단계(형식·검토·코드 검사·검토 거절)와 이유 |
| `08_dataset/<날짜>/*_label.jsonl` | `1_4_build_dataset.py` | 줄마다 룰 id·label·`sk`(샘플 지문)·생성 단계 기록(origin, review, local_check, note), `addr_fixed` |
| `07_llm_output/_progress/rule_status.csv` | `3_5_progress.py` | 룰별 상태 플래그 (DONE·EMPTY·FAILED 등) |
| `state.json` (받은 룰 파일 기록) | `1_1_fetch_rules.py` | 소스별 버전 표시(`marker`), 파일 위치, `sha256`, 크기, `downloaded_at` |

이 파일들은 `.gitignore` 로 저장소에 올라가지 않는다. 이 PC 에만 있다.

## 5.3 빈틈

| 빈틈 | 왜 문제인가 | 제안 |
| --- | --- | --- |
| `meta.json` 에 지시문 지문·temperature·추론 강도가 없음 | 같은 모델 이름이어도 지시문이 바뀌면 결과가 다름 → 재현·감사가 어려움 (R11) | 요청마다 `prompt_sha256`, `temperature`, `effort` 를 남김 |
| 사람의 기록에 '누가' 가 없음 | 여러 사람이 쓰면 승인자를 모름 (R12) | `edits.json`·설정 변경·버전 확정에 `by` 칸 (OS 사용자 이름 등) |
| 외부로 보낸 기존 payload 예시 수가 집계되지 않음 | 데이터 유출 노출량을 모름 (R05) | `meta.json` 에 `existing_examples_sent` |
| 연결 확인은 기록이 없음 | 의도된 설계(키를 화면 프로세스에 올리지 않음)지만 언제 어떤 모델을 시험했는지 모름 | 결과(성공·실패·모델·시각)만 설정 변경 기록에 함께 남김 |
| 확정 버전을 되돌리는 절차 없음 | 잘못 확정하면 다음 버전 기준이 오염 | 확정본 폐기 절차와 기록 형식을 문서로 |
