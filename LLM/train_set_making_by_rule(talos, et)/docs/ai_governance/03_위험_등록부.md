# 3. 위험 등록부 (ISO/IEC 42001 형식)

> ISO/IEC 42001:2023 의 AI 위험 평가(6.1.2)·위험 처리(6.1.3)·운영 중 위험 평가와 처리(8.2·8.3) 흐름을 따라 만든 **초안**이다.
> 표준 본문은 유료라 조항 번호는 ISO 공개 소개 페이지와 공개 요약을 기준으로 적었다 (확인 필요): https://www.iso.org/standard/42001
> 등급은 작성자의 판단이며 측정값이 아니다. 근거가 된 수치는 [4. 측정 지표](04_측정_지표.md) 에 출처와 함께 있다.

## 3.1 평가 척도

| 점수 | 가능성 (L) | 영향 (I) |
| --- | --- | --- |
| 1 낮음 | 지금 통제로 거의 일어나지 않음, 기록된 사례 없음 | 일부 샘플·한 실행에만 영향, 쉽게 되돌림 |
| 2 중간 | 일어난 기록이 있거나 조건이 맞으면 일어남 | 여러 룰·공격 유형의 학습데이터 품질, 하루 이상의 작업, 수십 달러 수준 비용 |
| 3 높음 | 자주 일어나거나 통제가 없음 | 확정 학습데이터에 들어가 탐지 모델에 영향, 민감값이 외부로 전달됨, 되돌리기 어려움 |

**위험 점수 = L × I** → 1~2 낮음, 3~4 중간, 6~9 높음. 고유 위험(통제 전)과 잔여 위험(지금 통제 후)을 따로 적는다.

**담당 역할** (사람 이름 대신 역할): 파이프라인 운영자(실행·모델 설정), 데이터 책임자(학습데이터 확정·외부 제공 데이터 판단), 보안 담당(키·외부 전송 검토), 탐지 모델 담당(데이터 사용·평가).

**검토 주기**: 기본은 **분기 1회** + 아래 '변경 계기'가 생길 때마다 (모델·provider 변경, 지시문 변경, 새 데이터 소스, 반기 버전 확정 전).

## 3.3 상세

### R01 안전 거부로 인한 라벨 분포 편향
- **원인**: 검토 모델이 명령 주입·RCE·인증 우회·오버플로·역직렬화 같은 위험 유형의 공격 샘플을 '안전하게 보존·수정할 수 없다' 며 빼거나 응답을 거절한다. 모델마다 정도가 크게 다르다.
- **영향**: 위험한 공격 유형일수록 학습데이터가 모자라 탐지 모델이 정작 중요한 공격을 덜 배운다. 한 실행에서 공격 샘플이 모두 빠진 룰 887개 (요약 163행).
- **NIST AI 600-1 범주**: Harmful Bias or Homogenization, Human-AI Configuration
- **지금 통제**
  - 거절 판정: 판정이 빠진 룰은 같은 모델로 '재시도 횟수'(3번)까지 다시 묻고, 그래도 없으면 통과시키지 않고 `검토 거절` 로 남김 — [`3_3_review.py`](../../3_3_review.py) `ask`, `review` (`refused`)
  - 안전 사유 문구 감지 `SAFETY_RE` 와 화면 문구 `EXCL_SAFETY` 를 맞춤 — `3_3_review.py` 60행, [`0_0_run_ui.py`](../../0_0_run_ui.py)
  - 사람이 누르는 '다시 만들기' (`--redo-safety`): 해당 룰만 대체 모델로 다시 검토, 옛 결과는 `_replaced/` 로 보관
  - 화면 2 '검토에서 뺀 샘플': 공격 유형별 표, **공격 샘플이 모두 빠진 룰** 열
  - 결과: 389개 요청 재검토로 공격 샘플 없는 룰 903 → 185 (요약 163행)
- **잔여 위험 (중간)**: 185개 룰은 여전히 공격 샘플이 없다. 대체 모델도 거절한 룰은 제외로 남고 다음 대상도 아니다. `SAFETY_RE` 는 문구 목록이라 새 표현을 놓칠 수 있다 (맞추기 전 344개를 놓쳤던 기록, README 206행). 유형별 삭제율의 기준선·경보는 없다.
- **추가 처리 (제안)**: 공격 유형별 삭제율을 실행마다 기록하고 기준을 넘으면 경고. 대체 모델도 거절한 룰 목록을 따로 관리해 사람이 직접 샘플을 만들지 판단.

### R02 라벨 오류
- **원인**: 생성 모델이 정규식을 잘못 읽음 (생성 샘플 약 30% 가 코드 검사 실패, 그중 37% 가 정규식 오해 — 요약 59행). 코드 검사는 위치 옵션(depth 등)을 근사로 본다. normal 이 '이 룰만 피한 공격'일 수 있다.
- **영향**: 확정 학습데이터에 틀린 라벨이 들어가 탐지 모델 성능이 떨어진다.
- **NIST AI 600-1 범주**: Confabulation, Information Integrity
- **지금 통제**: `local_check` 가 룰 기준으로 어긋난 샘플·판단 불가 샘플을 뺌 (`LLM_설정.md` `로컬 검사 실패 처리` = drop, `판정 불가 처리` = drop); 검토 뒤 코드 재검사 (`3_3_review.merge`); normal 교차 검사 (`normal 교차 검사` = 예); 정규식 예시 붙이기 (`3_2_generate.with_examples`); 화면 4 전체 검증·불일치 삭제; 화면 6 '불일치' 빼기 기본 켬.
- **잔여 위험 (중간)**: 코드 검사가 근사라 실제 Snort 로 확인하는 단계가 없다 (요약 66·180행 '남은 과제'). '정합(룰 기준)' 12.2% 는 공격 여부를 그 룰의 고유 패턴으로만 판단한 것이라 사람 판단 대기(보류 옵션) 상태다.
- **추가 처리 (제안)**: 확정 전 표본을 실제 Snort(WSL·Docker)로 돌려 탐지 일치율 측정.

### R03 로그 표기(직렬화)로 인한 라벨 불일치
- **원인**: 학습 로그가 줄바꿈을 두 글자 `\n` 으로 적어, 요청 줄에 글자 역슬래시+n 이 있으면 다시 읽을 때 줄이 잘림. payload 끝 `|` 와 구분자 `|||` 가 붙음.
- **영향**: 생성 때는 맞던 샘플이 학습 로그에서는 라벨과 어긋남. 190,226줄 중 110줄 (0.06%) (요약 65행).
- **지금 통제**: [`1_4_build_dataset.py`](../../1_4_build_dataset.py) 가 역슬래시를 `%5C` 로 적고, 끝 `|` payload 에 줄바꿈을 붙이며, 판정이 달라지면 뺌. 수정 뒤 불일치 0. 읽는 쪽은 label 을 마지막 `|||` 뒤로 읽음.
- **잔여 위험 (낮음)**: 형식이 바뀌면 다시 생길 수 있음 → 형식을 바꿀 때 전체 검증을 다시 돌림.

### R04 비용·구독 사용량 폭주
- **원인**: `--max-requests 0`(남은 전부), 재시도·반복 루프, 추론 모델의 긴 생각 토큰 (요청 하나에 10만~26만 — 설정 42행), Claude CLI 구독 한도를 사람의 사용과 함께 씀.
- **영향**: 예상 밖 API 비용, 사람이 Claude 를 못 쓰게 됨, 같은 요청에 두 번 비용.
- **지금 통제**: 기본 요청 수 1 (`3_0_run_generation.py` `--max-requests` default=1); `--dry-run`; 화면의 예상 시간·토큰과 확인 창; 생성 잠금 `.run/generation.lock` 으로 한 번에 하나만 (`3_0a_common.generation_guard`); 해석 실패 2번이면 건너뜀 (`3_2_generate.FAIL_LIMIT`); 크레딧 없음·로그인·구독 한도는 바로 멈춤 (`3_0a_common.FATAL_MARKS`); 잘린 룰만 다시 요청; 동시 요청 자동 조절 (`Throttle`); 모든 요청의 토큰을 `meta.json` `usage` 에 남김.
- **잔여 위험 (중간)**: 금액 기준 상한(예산)은 없다. 토큰 단가를 기록하지 않아 실행당 비용을 바로 알 수 없다. 추론 강도 기본값이 비어 있으면 모델 기본값을 씀.
- **추가 처리 (제안)**: 실행당 토큰 상한 설정 칸, 단가표로 실행당 추정 비용 기록.

### R05 참고 예시의 민감값 외부 전달
- **원인**: 생성 품질을 위해, 사용자가 넣은 기존 학습데이터에 샘플이 조금(1~50건) 있는 룰은 그 payload 몇 개(룰당 최대 3개, 1,500자 이하)를 '비슷하지만 똑같지 않게' 만들라는 참고 예시로 요청에 붙이는 기능이 있다 ([`3_1a_existing_coverage.py`](../../3_1a_existing_coverage.py) 194행, [`3_1_prepare_requests.py`](../../3_1_prepare_requests.py) 133행). 같은 요청 파일을 검토에도 쓴다 (`3_3_review.review_items`). 예시를 보내기 전에 값을 바꾸는 마스킹 단계는 아직 없다.
- **영향**: 참고 예시로 쓰는 기존 샘플에 Host·Cookie·Authorization·IP·이메일·토큰 같은 민감값이 섞여 있으면 그대로 외부 LLM 제공자에게 전달될 수 있다. 기존 샘플에 무엇이 들어 있는지는 쓰는 사람의 데이터에 따라 다르다.
- **NIST AI 600-1 범주**: Data Privacy, Information Security, Value Chain and Component Integration
- **지금 통제**
  - 끄는 스위치: `LLM_설정.md` `참고 예시 수` = 0 이면 예시 목록이 빈다 (`3_1_prepare_requests.py` 133행 `[:n_ex]`). `기존 데이터 참고 기준` = 0 이면 예시를 붙이는 구간 자체가 없다 (132행).
  - 기존 학습데이터를 넣지 않으면 예시도 없다 (3.1a 결과가 없으면 모든 룰을 '기존 0건' 으로 봄).
  - 데이터 폴더·`.env` 는 `.gitignore` 로 저장소에 올라가지 않는다.
- **잔여 위험**: 설정에 따라 다르다. 예시를 끄면 낮음, 켜고 마스킹이 없으면 기존 샘플의 민감도에 따라 높음까지, 마스킹을 넣으면 낮음.
- **계획한 통제**: 외부 전송 전 마스킹 단계, 기본값 켬 → [7. 마스킹 제안](07_마스킹_제안.md). 그 밖에 제공자별 데이터 보관·학습 사용 조건 기록, 요청마다 보낸 예시 수를 `meta.json` 에 남김.

### R06 API 키·OINKCODE 유출
- **원인**: `.env` 를 실수로 커밋, 로그·화면·오류 메시지에 키가 찍힘.
- **지금 통제**: `.env` 는 `.gitignore`, `.env.example` 만 공개; 로그의 OINKCODE 는 `****` ([`1_1_fetch_rules.py`](../../1_1_fetch_rules.py)); 화면은 키가 있는지만 보이고 값은 안 보임 (`0_0_run_ui.py` 2441행 주석); 연결 확인은 별도 프로세스 (키를 화면 프로세스에 올리지 않음); Claude CLI 자식 프로세스에서 `ANTHROPIC_*` 키를 뺌 (`3_0a_common._claude_cli_env`); 화면은 127.0.0.1 에만 열고 Host 확인 (`0_0_run_ui.py` 2803행).
- **잔여 위험 (중간: 영향이 커서)**: 키 교체 주기·비밀 검사(커밋 전 스캔) 도구는 없다.

### R07 룰 정규식 검사의 ReDoS
- **원인**: 룰 정규식 중 '반복 안의 반복'·'반복 안의 선택' 모양(약 7.5%)이 특정 입력에서 끝나지 않음. 3.1a 가 40분 넘게 멈춘 기록 (요약 154행).
- **지금 통제**: 위험한 모양만 `regex` 모듈로 검사 1번당 1초 제한 (`3_0a_common.REGEX_TIMEOUT`, `_risky`, `_guarded`), 넘으면 판단 불가로 둠, 시간 초과 룰 id·횟수를 로그에 남김; 생성 출력의 `{{REPEAT}}` 펼침 길이 상한 2만 자 (`REPEAT_MAX_CHARS`); 증강용 문자열 길이 상한 (`_MAX_GEN`).
- **잔여 위험 (낮음)**: `regex` 모듈이 없으면 그 모양은 검사하지 않고 판단 불가 → 그 룰의 샘플이 빠져 R01 처럼 커버리지가 줄 수 있다.

### R08 제공자 장애·크레딧 소진·모델 변경
- **원인**: 429·5xx, 크레딧 소진(2026-10-26 실제 발생 — 설정 18행), 모델 이름 변경·폐기, 모델을 바꾸면 안전 거부·수정 성향이 달라짐.
- **지금 통제**: 재시도·429 대기 (`call_llm`, `RATE_LIMIT_WAITS`); 크레딧 없음은 바로 멈추고 다음 실행 때 이어서; 단계마다 끝난 요청은 건너뜀 (멈춰도 이어서); provider 표로 교체 가능 (`LLM_설정.md`); `mock` 으로 키 없이 흐름 시험; 모델을 바꿀 때 소량 비교를 문서에 남긴 기록 (20건·10건·30건).
- **잔여 위험 (중간)**: 생성 모델은 하나뿐이다. 모델 교체 때 쓰는 고정 회귀 세트·통과 기준이 없다.

### R09 룰 텍스트를 통한 프롬프트 인젝션
- **원인**: 외부 룰(ET Open·Talos·사용자 룰)의 `msg`·원문이 그대로 지시문 뒤에 들어간다. 악의적인 룰 문구가 모델 지시를 바꿀 수 있다.
- **지금 통제**: 출력은 JSON 으로만 해석 (`parse_json_lines`), 다른 형식은 버림; 라벨은 LLM 이 아니라 코드 검사가 룰 조건으로 정함; Claude CLI 는 도구 없음·안전 모드·MCP·훅·세션 기록 없이 빈 임시 폴더에서 실행 (`_call_claude_cli` 의 `--tools ""`, `--safe-mode`, `--strict-mcp-config` 등); API 호출은 도구 없는 채팅 요청; 룰 파일은 버전·`.md5`/`version.txt` 비교와 sha256 기록 후 받음 (`1_1_fetch_rules.py`).
- **잔여 위험 (낮음)**: 인젝션으로 검토 모델이 `pass` 를 남발해도 코드 검사를 통과해야 남는다. 다만 `note` 같은 자유 문구 필드에 엉뚱한 글이 들어갈 수 있다.

### R10 생성 데이터의 비현실성
- **원인**: 안전 규칙 때문에 문서용 IP·`example.com` 사용 (생성 공격의 32.5%), 인코딩 과다, 본문 공격·짧은 자동화 요청 부족 (요약 61·66행).
- **영향**: 모델이 '이 주소 = 공격' 같은 가짜 신호를 배움.
- **NIST AI 600-1 범주**: Harmful Bias or Homogenization, Information Integrity
- **지금 통제**: 학습 로그 변환 때 문서용 주소를 샘플마다 다른 주소로 바꿈 (판정이 달라지면 원래대로); 헤더 현실화; 기존 데이터와 비교해 등급(A·B·C)으로 선별, 패턴당 상한; rule_id 지문으로 30% holdout (평가 오염 방지).
- **잔여 위험 (중간)**: 공격 형태 분포 맞추기는 '다음 단계'로 남아 있음 (요약 181행).

### R11 문서·기록 동기화
- **원인**: 모델을 여러 번 바꾸는 동안 일부 문서의 검토 모델 표기가 예전 값으로 남았다 — 설정 파일 `LLM_설정.md` 는 gpt-6-luna, README·`3_3_review.py` 주석은 Claude CLI sonnet, `LLM_프롬프트.md` 주석은 gpt-5 ([1장 1.2](01_AI_시스템_목록.md#12-문서-동기화가-필요한-곳)). `meta.json` 에는 모델 이름은 있지만 **지시문 지문(해시)·temperature·추론 강도**는 없다 (`3_2_generate.py` 118~123행, `3_3_review.py` 241~247행).
- **영향**: 나중에 "이 샘플은 어떤 지시문·설정으로 만들었나" 를 정확히 답하기 어렵다 (감사·재현성).
- **지금 통제**: `meta.json` 의 `generator`·`reviewer`·`fallback.model`; 모델 설정 변경 기록 `logs/llm_settings_changes.jsonl` (화면에서 바꾼 경우만, `0_0_run_ui.py` 2749행); 지시문은 git 이력.
- **잔여 위험 (중간)**. 추가 처리는 [다음에 할 일](README.md#다음에-할-일).

### R12 사람 결정의 증적 부족
- **원인**: 단일 PC·단일 사용자 도구라 기록에 '누가' 가 없다.
- **지금 통제**: 수정·삭제는 `edits.json` 에 사유(`why`)·시각(`at`)·원래 라벨, 되돌리기 가능; 버전 확정은 `manifest.json` 에 조건·옵션·파일 sha256·확정 시각; 다시 만들기는 `meta.json` `redo`(시각·모델); 모델 설정 변경 기록.
- **잔여 위험 (낮음)**: 여러 사람이 쓰게 되면 승인자 기록이 필요.

### R13 룰 라이선스
- **원인**: Talos 룰은 재배포 제한이 있다 (README '주의 사항').
- **지금 통제**: 공개 저장소에 룰·데이터를 올리지 않음 (`.gitignore`); README 에 주의 문구.
- **NIST AI 600-1 범주**: Intellectual Property
- **잔여 위험 (낮음)**: 룰에서 만든 학습데이터를 밖에 줄 때의 라이선스 해석은 확인 필요.
