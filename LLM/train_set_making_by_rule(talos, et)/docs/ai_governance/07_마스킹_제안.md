# 7. 참고 예시 마스킹 (설계 → 구현, 2026-10-29)

> 위험 등록부 [R05](03_위험_등록부.md#r05-참고-예시의-민감값-외부-전달) 의 통제다. 처음에는 설계 제안이었고, 2026-10-29 에 [`3_0b_mask.py`](../../3_0b_mask.py) 로 구현해 [`3_1_prepare_requests.py`](../../3_1_prepare_requests.py) 에 붙였다. 기본 켬.

## 7.1 목적

참고 예시(`existing_examples`)는 생성 모델이 '비슷하지만 똑같지 않은' 샘플을 만들도록 돕는다. 예시에 필요한 것은 **공격 부분의 모양**(경로·파라미터·페이로드 구조)이지 Host·쿠키·인증값 같은 환경 값이 아니다.
그래서 예시를 LLM 에 보내기 전에 환경 값과 민감값을 **자리표시 값으로 바꾸고**, 바꾼 뒤에도 룰 조건을 만족하는지 다시 확인한다.

원칙:
- **기본값 켬.** 끄려면 설정에서 명시적으로 끈다 (`LLM_설정.md` `참고 예시 마스킹` = 아니오, 비교용).
- **실패하면 막는다(fail closed).** 마스킹 중 오류가 나면 그 예시는 보내지 않는다.
- **원래 값은 어디에도 남기지 않는다.** 로그·`meta.json`·manifest 에는 바꾼 개수만.

## 7.2 넣은 곳

| 위치 | 하는 일 |
| --- | --- |
| [`3_0b_mask.py`](../../3_0b_mask.py) `mask_example(text)` | 예시 하나 → (바꾼 글, {종류: 개수}). 처리할 수 없으면 `MaskError` |
| `3_0b_mask.py` `safe_examples(C, examples, rule, n)` | 후보를 차례로 마스킹 → 룰 보존 확인 → 통과한 것만 최대 n개. 오류·룰 조건 깨짐은 빼고 다음 후보로 채움 |
| [`3_1_prepare_requests.py`](../../3_1_prepare_requests.py) `main` (기존 1~50건 룰에 `existing_examples` 를 붙이는 곳) | 설정이 켜져 있으면 `safe_examples` 를 거친 예시만 붙임. 룰마다 `_mask`(바꾼 값 수·뺀 예시 수)를 기록 |
| 3.1 조건 지문 | 마스킹 설정·규칙 버전(`VERSION`)이 들어감 → 켜거나 규칙을 바꾸면 아직 생성하지 않은 요청 파일을 다시 만듦 |
| [`3_2_generate.py`](../../3_2_generate.py) `user_message`, [`3_3_review.py`](../../3_3_review.py) `review_items` | `_mask` 칸을 LLM 에 보내지 않음 |

- 생성(3.2)·검토(3.3) 모두 이 요청 파일을 쓰므로 한 곳에서 둘 다 막힌다.
- 로컬 `coverage.json`(3.1a 결과)에는 원래 예시가 남는다 (외부로 가지 않음). 3.1a 쪽 마스킹(처음 설계의 후보 B)은 하지 않았다: 설정을 바꿀 때마다 3.1a 를 다시 돌려야 하기 때문.
- 표준 라이브러리만 쓴다 (`re`, `ipaddress`).

## 7.3 바꾸는 값

자리표시 값은 생성 지시문의 안전 규칙(문서용 IP·`example.com`)과 맞췄다. 그러면 학습 로그를 만들 때(1.4 '문서용 주소 바꾸기') 샘플마다 다른 값으로 다시 바뀐다.

| 대상 | 찾는 방법 | 바꾼 값 |
| --- | --- | --- |
| `Host` 헤더 값 | 헤더 줄 `Host:` | `www.example.com` (포트는 유지) |
| `Cookie`·`Set-Cookie` 헤더 | 헤더 줄 | 이름은 두고 값만 `x` (`SESSIONID=x; lang=x`) |
| `Authorization`, `Proxy-Authorization` | 헤더 줄 | 방식만 남김: `Bearer TOKEN`, `Basic dXNlcjpwYXNz`(user:pass), 그 밖은 `<방식> x` |
| `Referer`·`Origin` 의 호스트 | 헤더 줄 | `example.com` (경로·포트는 유지, URL 안의 사용자 정보는 지움) |
| IPv4 / IPv6 (요청 줄·헤더·본문 어디든, `X-Forwarded-For` 등 포함) | `ipaddress` 로 검증되는 문자열 | `192.0.2.<n>` / `2001:db8::<n>` (같은 예시 안의 같은 값은 같은 값으로) |
| 이메일 | `[\w.+-]+@[\w-]+(\.[\w-]+)+` | `user@example.com` |
| JWT | `eyJ` 로 시작하고 점 두 개로 나뉜 값 | `eyJ0eXAiOiJKV1QifQ.e30.x` |
| 이름이 비밀인 파라미터·필드 값 | 이름이 `token`, `api_key`·`apikey`, `key`, `secret`, `session`·`session_id`, `sid`, `password`·`passwd`, `pwd`, `auth` 이거나 `_`·`-`·`.` 뒤에 이것이 붙은 이름(`access_token`, `client_secret` 등) 인 쿼리·폼·JSON 값 (대소문자 무시) | 같은 길이의 `x` (최대 16자) |
| 긴 무작위 값 | 32자 이상의 16진수 덩어리 / 32자 이상의 base64 같은 값 (대·소문자·숫자가 섞이고 글자 종류 12개 이상) | `0` 32개 / `x` 32개 |

**바꾸지 않는 것**
- 메서드·경로·공격 페이로드·룰 조건에 쓰인 문자열.
- 루프백(`127.0.0.1`, `::1`)·링크 로컬(`169.254.169.254` 같은 메타데이터 주소)·`0.0.0.0`·멀티캐스트·이미 문서용인 주소: 공격 내용인 경우가 많고 민감하지 않다.
- `Chrome/124.0.0.0` 같은 브라우저 버전 (IP 모양이지만 앞이 `글자/`).
- `AAAA…` 같은 반복, `/wp-content/plugins/…` 같은 경로 (무작위 값으로 보지 않음).

## 7.4 룰 보존 확인

마스킹 뒤 **원래 만족하던 룰 조건이 모두 여전히 만족하는지** 확인한다 (`rule_kept`: 조건마다 `C.check_condition` 을 마스킹 전·후로 비교 — 3.1a 가 예시를 고를 때와 같은 검사).

- 만족 → 마스킹한 예시를 보냄.
- 불만족 (룰 조건이 바꾼 값 안에 있었음, 예: 조건이 `Cookie` 안) → 그 예시는 **보내지 않음**. 원래 값을 그대로 보내는 길은 없다. 다음 후보로 채운다.
- 예시가 모두 빠진 룰은 예시 없이 일반 생성으로 간다 (기존 0건 룰과 같은 흐름, `existing_examples` 칸 없음).

## 7.7 측정

로컬 예시 후보 전체에 마스킹을 돌려 **개수만** 셌다 (`python 3_0b_mask.py --measure`: 가장 최근 3.1a 결과를 읽고 파일은 쓰지 않음, 원래 값은 출력하지 않음). 미리 보기는 `python 3_1_prepare_requests.py --dry-run` (요청 파일·manifest 를 쓰지 않고 로그에 수만).

| 지표 | 값 (2026-10-29) |
| --- | --- |
| 바꿀 값이 하나 이상 있던 예시 후보 | 99% (대부분 Host 헤더) |
| 마스킹 오류로 뺀 예시 | 0 |
| 룰 조건이 깨져 뺀 예시 | 후보의 약 3% |
| 예시가 모두 빠져 일반 생성으로 가는 룰 | 예시 대상 룰의 약 6% |
| 보낼 예시 하나당 바꾼 값 | 평균 약 1.3개 |

## 7.8 남는 한계

- 패턴 기반이라 이름이 평범한 파라미터에 든 비밀값·개인정보(예: `q=<개인 이름>`, 전화번호)는 못 잡는다. 그래서 `참고 예시 수` = 0 스위치는 그대로 둔다.
- 마스킹으로 예시가 빠지면 그 룰의 생성 품질이 조금 떨어질 수 있다. 빠진 예시 수를 기록해 보고 판단한다.
- 마스킹을 넣기 전에 보낸 예시는 되돌릴 수 없다.
- 사용자 룰을 넣으면 그 룰 원문도 LLM 에 간다 (마스킹 대상이 아님).
- LLM 제공자별 데이터 보관·학습 사용 조건 기록은 별도 할 일이다 ([README 다음에 할 일](README.md#다음에-할-일) 2번).
