# AI 작업 규칙 (이 저장소)

이 저장소에서 일하는 AI 코딩 도구가 공통으로 읽는 규칙이다.
Codex·Cursor 등은 이 파일을 직접 읽고, Claude Code 는 `CLAUDE.md`, Gemini 는 `GEMINI.md` 가 이 파일을 가져온다.
규칙은 이 파일 한 곳에만 쓴다.

- 답은 한국어로 한다.
- 코드를 새로 쓰거나 고친 뒤 [docs/ai_governance/코드_검토_원칙.md](docs/ai_governance/코드_검토_원칙.md)의 점검 질문으로 검토한다.
  - 보고에 '검토'를 몇 줄 남긴다: 뺀 것 · 단순하게 한 것 · 남긴 복잡성의 까닭.
- 무엇이 어디 있는지는 `README.md`, 단계별 설정·지시문은 `docs/코드참조/`에 있다.

## 꼭 지킬 규칙

1. API 키는 `.env`에만 둔다. 키 값을 출력하거나 붙여 넣지 않는다.
2. `06_기존 데이터`, 회사 룰(`00_custom_rules`) 내용, 회사 정보, `12_server/` 레시피 내용은 공개 파일에 넣지 않는다.
   - 룰은 id·요약만 쓴다.
3. 유료 LLM 실행은 사용자의 직접 승인을 받는다.
4. 생성·수집·다시 만들기가 도는 동안 파이프라인(`1_x`·`3_x`·`4_1`·`docs/코드참조`)을 고치지 않는다.
   - 도는지는 `.run/*.lock`으로 안다.
5. 고치기 전 원본을 `_보관/<날짜>_<이름>_전/`에 둔다.
   - 삭제는 승인을 받고, 먼저 `_보관`으로 옮긴다.
6. CRLF 파일에 `sed -i`를 쓰지 않는다 (줄바꿈이 LF 로 바뀐다).
7. 공개 내보내기는 `0_9_export_public.py`와 그 금지어(FORBID) 검사로만 한다.
8. 이 규칙 파일들에 회사·룰 값 같은 민감한 내용을 적지 않는다.
