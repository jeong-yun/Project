# NotebookLM 소스팩 생성 (nlm-pack)

## 핵심 전제

NotebookLM은 **source-grounded** 다. 업로드한 소스에 없는 내용은 영상에 나오지 않고, 소스에 있는 표현은 거의 그대로 반영된다. 즉 **소스팩 품질 = 영상 품질**이고, 프롬프트로 없는 내용을 끌어낼 수는 없다.

그래서 이 단계의 일은 "요약"이 아니라 **NotebookLM이 읽을 것을 전제로 쓴 대본형 문서를 만드는 것**이다. 강조하고 싶은 문장은 소스에 그 문장으로 써 넣어야 한다.

작업 전 `references/notebooklm-settings.md` 를 읽는다. 포맷별 언어 제약과 UI 설정값이 거기 있고, 특히 **한국어 short 은 NotebookLM 네이티브로 불가능**하다는 제약이 산출물 구성을 바꾼다.

## 입력

`IT 개념/<slug>/00-research.md` (it-verify 산출물). 없으면 먼저 `it-verify` 를 돌린다 — 검증되지 않은 내용으로 소스팩을 만들면 이 파이프라인의 존재 이유가 사라진다.

팩트시트의 `영상에 쓰지 말 것` 목록은 소스팩에 **절대 넣지 않는다.** 소스에 들어가면 NotebookLM이 그걸 사실로 낭독한다.

## 산출물 4개

| 파일 | 용도 |
|---|---|
| `10-source-long.md` | 일반 버전(Explainer, 16:9) NotebookLM 소스 |
| `20-source-short.md` | short 버전(60초) NotebookLM 소스 + 나레이션 원고 |
| `30-checklist.md` | NotebookLM UI 조작 순서 + steering prompt 붙여넣기용 |
| `meta.json` | 상태 추적 (2단계 자동화에서 사용) |

## 1. 일반 버전 소스팩 (`10-source-long.md`)

목표 6~10분. 아래 구조로 쓴다 — Explainer 포맷이 소스의 헤딩 구조를 슬라이드 흐름으로 거의 그대로 따라가기 때문에, 헤딩이 곧 스토리보드다.

```markdown
# <개념명> — 무엇이고 왜 생겼나

## 1. 이 영상에서 답할 질문
<3개 질문. 시청자가 검색창에 칠 법한 문장으로>

## 2. 문제 상황: <개념>이 없던 시절
<이 기술이 해결한 고통을 구체적 장면으로. 추상적 서술 금지>

## 3. 한 줄 정의
## 4. 비유
<비유 1개만. 그리고 "이 비유가 깨지는 지점" 을 반드시 함께 적는다>
## 5. 동작 원리
<단계별. 각 단계마다 "그래서 무엇이 좋아지는가" 를 붙인다>
## 6. 실제 사례
<제품·서비스 이름과 어떻게 쓰는지>
## 7. 흔한 오해 정정
## 8. 언제 쓰면 안 되는가
## 9. 30초 요약
## 부록: 용어 정리
<영어 약어의 원어 표기 — 나레이션 발음 품질에 직접 영향을 준다>
```

작성 규칙:
- **비유는 1개만.** 비유가 여러 개면 NotebookLM이 섞어서 앞뒤가 안 맞는 설명을 만든다.
- 표와 리스트를 적극적으로 쓴다. Explainer가 시각 요소로 잘 옮긴다.
- 팩트시트의 출처 URL은 본문에 넣지 않고 문서 맨 끝 각주로 몰아둔다. 본문에 있으면 나레이션이 URL을 읽으려 한다.
- 한 문단은 3문장 이내. 긴 문단은 슬라이드 하나에 몰려 들어가 읽히지 않는다.

## 2. short 버전 소스팩 (`20-source-short.md`)

**아이디어 하나만.** 팩트시트의 `흔한 오해` 또는 `논쟁 지점`에서 고르는 게 보통 가장 강하다 — 반전이 있는 소재라야 60초를 버틴다.

```markdown
# <훅 문장>

## 이 클립의 단 하나의 메시지
<한 문장. 이것만 남으면 성공>

## 나레이션 원고 (60초)
[0-5초] 훅
[5-20초] 왜 그렇게 생각하는지 (공감)
[20-45초] 실제로는 이렇다 (핵심)
[45-60초] 그래서 뭐가 달라지나 + 마무리

## 화면에 떠야 할 텍스트
<자막용 짧은 구절 4~6개>

## 절대 언급하지 말 것
<곁가지 개념들. 60초에 들어오면 전부 망친다>
```

나레이션 원고 분량은 **한국어 250~320자**를 기준으로 잡는다(한국어 발화 속도 대략 분당 300음절 내외). 넘으면 반드시 줄인다 — 60초를 넘긴 원고는 어떤 도구로 만들어도 잘린다.

원고를 직접 쓰는 이유: 한국어 short은 NotebookLM으로 못 만들기 때문에 TTS·편집 도구로 넘어가야 하고, 그때 이 원고가 그대로 입력이 된다. NotebookLM 소스로도 쓰이고 대체 경로 입력으로도 쓰이는 이중 용도 문서다.

## 3. 체크리스트 (`30-checklist.md`)

사람이 NotebookLM UI에서 클릭할 순서를 그대로 쓴다. steering prompt는 **복사해서 붙여넣을 수 있게 코드블록**에 넣는다.

steering prompt 작성법 — 짧은 명령형이 잘 먹는다. 200자 내외로:
- 무엇에 집중할지 (소스 안의 특정 섹션을 지목)
- 무엇을 빼라 (곁가지)
- 톤 (예: 실무 개발자 대상, 과장 없이)

`references/notebooklm-settings.md` 의 포맷·언어·비주얼 스타일 권장값을 체크리스트에 반영한다.

## 4. meta.json

```json
{
  "slug": "", "title_ko": "", "title_en": "",
  "verified_at": "YYYY-MM-DD",
  "stage": "packed",
  "long": {"format": "explainer", "lang": "ko", "visual_style": "", "generated": false, "video_path": null},
  "short": {"route": "", "lang": "ko", "narration_chars": 0, "generated": false, "video_path": null}
}
```

`stage` 는 `verified` → `packed` → `generated` → `published` 로 진행한다. 2단계 자동화가 이 필드를 보고 다음 작업을 고른다.

## 끝낸 뒤

사용자에게 알려줄 것:
1. 만든 파일 경로 4개
2. **short 을 어떤 경로로 갈지** (NotebookLM 불가 제약 때문에 선택이 필요하다)
3. NotebookLM에서 눌러야 할 것 요약 3줄
