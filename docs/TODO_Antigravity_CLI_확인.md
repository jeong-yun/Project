## 왜 남았나

사용법 문서는 공식 문서·agy 내장 안내·변경 기록과 맞춰 썼다. `agy` 를 켜서 대화하는 것은 해 보지 못했다. 문서를 Claude Code 로 썼고, 위 약관 때문에 Claude Code 가 대신 켜지 않았기 때문이다.

## 1. 이 PC 에서 먼저 고칠 것

- [ ] **저장소 폴더에서 켠다.** 지금까지는 사용자 홈 폴더와 저장소의 윗폴더(`Project` 를 담은 폴더)에서 켰다(agy 기록 파일). 두 곳에서는 이 저장소의 `AGENTS.md` 가 실리지 않는다. 앞으로는 `Project` 나 `Project\LLM\Agent_office` 에서 켠다.
- [ ] **'믿는 폴더' 목록에서 홈 폴더를 뺀다.** 지금 목록에 사용자 홈 폴더와 저장소의 윗폴더가 들어 있다.
  - 방법: `agy` 를 끄고 `C:\Users\<사용자>\.gemini\antigravity-cli\settings.json` 을 메모장으로 열어 `trustedWorkspaces` 목록에서 그 줄을 지운다.
  - `/config` 화면에서 지울 수 있는지는 확인하지 못했다. 되면 그쪽이 쉽다.

## 2. 켜서 확인할 것 (이 PC, 10분쯤 — 추정)

| | 할 일 | 볼 것 | 문서와 다르면 고칠 곳 |
|---|---|---|---|
| [ ] | `Project` 에서 `agy` → `/context` | 아래쪽 파일 목록(System files)에 루트 `AGENTS.md` 가 나오는가 | 사용법 2절 '어느 폴더에서 켜느냐' |
| [ ] | `Project\LLM\Agent_office` 에서 `agy` → `/context` | `AGENTS.md` 가 두 개(루트 + Agent Office) 나오는가 | 사용법 2절 표 |
| [ ] | `Project` 에서 `agy --add-dir LLM\Agent_office` → `/context` | Agent Office 의 `AGENTS.md` 도 나오는가 | 되면 사용법 2절에 이 방법을 추가 |
| [ ] | `git worktree add` 로 만든 폴더에서 `agy` → `/context` | 루트 `AGENTS.md` 가 나오는가 (저장소 루트를 제대로 찾는가) | 사용법 4절 '앱을 돌리는 폴더에서 켜지 않는다' |
| [ ] | 입력 칸에 한글을 쳐 본다. Shift+Enter 로 줄을 바꿔 본다 | 글자가 깨지거나 밀리지 않는가. 줄이 바뀌는가 (안 되면 Ctrl+J) | 사용법 3절 '입력' |
| [ ] | Shift+Tab 을 여러 번 누른다 | accept-edits 다음에 바로 plan 이 나오는가 (이 PC 는 auto 가 안 된다고 기록에 나옴) | 사용법 3절 '권한 모드' |
| [ ] | 첫 화면부터 로그인까지의 순서를 떠올려 적는다 | 색 → 그리는 방식 → 폴더 믿기 → 로그인 순서였는가. 수집 동의 칸이 있었는가 | 사용법 1-3 |
| [ ] | 한 번 쓰고 나서 `Project` 에서 `git status` | 새 파일이 생기지 않았는가 | 생겼으면 `.gitignore` 에 넣을지 정한다 |

## 3. 조건이 될 때 확인할 것

- [ ] **다른 PC 에서 처음 설치할 때** 사용법 1절이 적힌 순서대로 되는가 (설치 명령 → 새 터미널 → 저장소 받기 → 로그인).
- [ ] **auto 모드가 되는 PC 에서** (Windows 11 24H2 + 2026년 8월 업데이트 이상) `python -m pytest -q` 와 올리기 전 검사(`git push`)가 격리된 공간(샌드박스) 안에서도 도는가.
- [ ] **`.env` 읽기를 막고 싶을 때** `/permissions` 에 `read_file(.env)` 거부 규칙을 넣고, `LLM\Agent_office\.env` 처럼 하위 폴더의 파일도 막히는지 본다. 실제 키가 든 파일 말고, 가짜 값만 넣은 연습용 `.env` 로 시험한다.
